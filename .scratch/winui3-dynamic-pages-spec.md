## 问题陈述（Problem Statement）

在为 unbound-ui 的像素级一致性校验采集官方 WinUI 3 控件参考截图时，当前参考宿主（`tools/winui-reference`）采用的是“单控件独立拼版（Single-Control Sheet）”机制：全量 66 个基准控件与 2 套主题（Light/Dark）被拆分为 132 个独立批次，每个批次均需经历一次完整的窗口加载、布局计算、至少 350ms 的控件动效收敛等待与独立截图导出。
这一模式导致即使仅跑单个主题的基准采集，开发者也必须等待长达近一分钟；若在调试时仅想校验若干控件，也无法将多控件紧凑合并到同屏一次性核验，吞吐量低下且反馈循环冗长。

## 解决方案（Solution）

升级 WinUI 3 参考采集宿主，引入**动态拼版页（Dynamic Parity Page）**与**用例装箱（Case Bin Packing）**管线：
1. **用例级与控件级增量过滤**：运行时先比对用例指纹，已全部命中缓存的控件完全不进入视口；仅将未命中缓存或用户显式指定需要采样的控件状态送入待采队列。
2. **多控件 2D 流式装箱分页**：在固定的确定性标准视口（`1920×1080 DIP`）内，将多个不同控件的状态以流式网格紧凑拼版；单页填满后自动流向下一页（全量 66 个控件单主题仅需 2~3 页）。
3. **单窗口清空复用与单次动效收敛**：保持单个持久窗口实例，每页仅等待一次 350ms 动效收敛，单次导出整页大图；随后立即在后台按各槽位控件的相对视觉几何与出血边距切出独立的紧凑单图与单用例元数据。
4. **瞬态载体与切片产物解耦**：整页拼版仅作为瞬态采集载体，排版坐标漂移不影响单图切片像素与用例指纹，保证增量缓存颗粒度依然精准到单用例，下游 Rust 差分器与四重门禁零改动向后兼容。

## 用户故事（User Stories）

1. 作为框架开发者，我希望在批量采集 WinUI 3 参考图时，系统自动将所有待采控件的状态紧凑拼入少量大页面中一次性截图，以便将等待 350ms 动效收敛的次数从上百次降至个位数，全量采集耗时缩短 30 倍。
2. 作为框架开发者，我希望已被用例指纹增量缓存命中的控件完全不出现在任何拼版页中，以便只对真正变更的控件分配版面和渲染等待。
3. 作为框架开发者，我希望单页具有确定性的标准视口上限（1920×1080 DIP）并在槽位超出时自动安全分页，以便在不同开发机与 CI 环境下均能生成稳定、不被系统裁剪的采集大图。
4. 作为框架开发者，我希望多页翻页在同一个窗口内就地清空并装载下一页，以便避免频繁创建/销毁 HWND 导致的窗口闪烁与 DWM 重建延迟。
5. 作为框架开发者，我希望无论控件排在拼版页的哪个坐标，最终生成的单图依然是 `<Control>_<state>_<theme>.png` 并拥有独立指纹与元数据，以便保持单用例缓存隔离且与现有下游差分器完全向后兼容。
6. 作为框架开发者，我希望在使用 `--save-sheet` 时获得按页码归档的总览图（`page_{index}_{theme}_{backdrop}_sheet.png`）及记录各槽位包围盒的索引 JSON，以便直观全局核对该页所有控件的视觉质感与排版坐标。
7. 作为框架开发者，我希望通过命令行 `--control <Name>` 过滤采集单个控件时，该控件的所有状态自动排入 Page 0 并在数秒内完成采集，以便在单控件迭代时获得即时反馈。

## 实现决策（Implementation Decisions）

- **动态多控件用例装箱与分页数据模型**：
  构建 `DynamicParityPage` 批次模型，按 `(theme, backdrop)` 归类。以控件为最小筛选单元：只要控件内有任意状态未命中缓存或属于用户指定目标，即收集该控件所有支持状态；将各状态槽位放入 `1920×1080 DIP` 的流式排版规划器，槽位自适应计算 DesiredSize + BleedMargin，超出可用高度则自动封包当前页并流向下一页。
- **单窗口生命周期与渲染收敛**：
  保持单个 `Window` 实例，将根容器设为固定 `1920×1080 DIP` 的画板。装载当前页的全部控件槽位后，启动 3 帧渲染循环与 350ms 动效计时器；计时完成后触发单次 `RenderTargetBitmap.RenderAsync`，获取整页 BGRA 像素缓冲；随后就地调用 `Host.Children.Clear()` 并推进至下一页。
- **异步切片与独立单用例持久化契约**：
  大图截取完成后，遍历当前页激活的槽位列表，通过 `control.TransformToVisual(Host)` 获取每个槽位在整页中的物理像素包围盒（并加上 16 DIP 出血保护）；切出紧凑单图，写入 `<Control>_<state>_<theme>.png` 与包含 `fingerprint`、`controlBounds` 的同名 JSON。
- **总览存档契约演进**：
  开启 `--save-sheet` 时，输出 `page_{pageIndex:D2}_{theme}_{backdrop}_sheet.png`，并配套写入包含本页控件清单与各槽位相对包围盒的 `page_{pageIndex:D2}_{theme}_{backdrop}_sheet.json`。
- **架构决策记录**：
  新建 `docs/adr/0015-dynamic-multi-control-parity-pages.md`，阐明解耦瞬态采集载体与切片独立产物的取舍与演进，正式取代 ADR 0008 中备选方案关于巨型图集坐标漂移的顾虑。

## 测试决策（Testing Decisions）

- **测试标准**：以黑盒命令行与文件契约作为最高层级接缝，只验证外部输入参数与输出切片及缓存行为，不测流式装箱的内部数据结构。
- **测试接缝**：以 `WinUiReference.exe` CLI 作为唯一最高层级测试接缝：
  1. **全量批处理冒烟与切片完整性测试**：执行 `--batch --out <temp_dir>`，验证返回码为 0，输出目录中成功生成全部 66 个控件对应状态的紧凑单图与 JSON；
  2. **增量指纹跳过测试**：在不清理输出目录的前提下二次执行同一命令，验证日志输出 `[cache-hit]` 且耗时为毫秒级（跳过全部页面渲染）；
  3. **单控件即时过滤测试**：执行 `--batch --control Button --no-cache --out <temp_dir>`，验证仅生成 Page 0 且仅包含 Button 的状态单图；
  4. **总览图与索引测试**：执行带 `--save-sheet`，验证生成 `page_00_*_sheet.png` 与配套 JSON；
  5. **下游差分链路集成测试**：运行 `showcase --parity-run --reference <temp_dir>`，验证 Rust 端离屏差分器能正确消费切片单图并输出 100% 格式合规的 `report.json`。
- **现有同类测试先例（Prior Art）**：
  - `tools/winui-reference/README.md` 中的标准采集与差分工作流；
  - `apps/showcase/src/parity.rs` 中的参考图消费与 ROI 门禁验证。

## 范围之外（Out of Scope）

1. 不改动 Rust 端 `showcase --parity-run` 的无头 GPU 渲染器内部逻辑与 CIEDE2000 四重门禁算法。
2. 不在单页内混排不同的 `theme`（Light/Dark）或 `backdrop`（Solid/Mica/Acrylic），保持批次间环境纯净。
3. 不变更各个具体控件在 `Catalog.cs` 中现有的确定性文案与展示尺寸配方。
