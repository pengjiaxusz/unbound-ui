# 范围之外知识库（Out-of-Scope Knowledge Base）

仓库中的 `.out-of-scope/` 目录用于持久化记录被拒绝的特性请求。它有两个作用：

1. **组织记忆**：记录某项特性为什么被拒绝，避免 issue 关闭后推理过程随之丢失
2. **去重**：当新进 issue 与过往被拒请求匹配时，技能能直接调出历史决策，免于反复争论

## 目录结构

```
.out-of-scope/
├── dark-mode.md
├── plugin-system.md
└── graphql-api.md
```

按**概念（concept）**建文件，而不是按 issue 建文件。多个请求同一件事的 issue 归并到同一份文件下。

## 文件格式

风格应轻松易读，更像一篇简短的设计备忘，而不是数据库条目。善用段落、代码示例和例子，让第一次看到它的人也能一眼明白背后的考量。

```markdown
# Dark Mode

本项目不支持深色模式或面向用户的主题切换。

## 为什么不在范围内

渲染流水线假设只存在定义在 `ThemeConfig` 中的单一调色板。支持多主题将需要：

- 包裹整个组件树的主题上下文 Provider
- 每个组件支持按主题解析样式
- 用户主题偏好的持久化层

这是一项重大的架构变更，与本项目聚焦内容创作的定位不符。主题定制属于下游嵌入或二次分发方的职责。

```ts
// 当前 ThemeConfig 接口并非为运行时切换设计：
interface ThemeConfig {
  colors: ColorPalette; // 单一调色板，构建期解析
  fonts: FontStack;
}
```

## 历史请求

- #42: "Add dark mode support"
- #87: "Night theme for accessibility"
- #134: "Dark theme option"
```

### 文件命名

为概念起一个简短、描述性的 kebab-case 名称：`dark-mode.md`、`plugin-system.md`、`graphql-api.md`。名称应足够直观，让人扫一眼目录就知道被拒的是什么。

### 撰写拒绝理由

理由必须有实质内容：不是“我们不想要”，而是*为什么*。好的理由会引用：

- 项目定位或哲学（“本项目聚焦于 X；主题属于下游关注点”）
- 技术约束（“支持它需要 Y，这与我们的 Z 架构冲突”）
- 战略取舍（“我们选择用 A 而不是 B，因为……”）

理由应当持久有效。避免引用临时处境（“我们现在太忙了”）；那不是真正的拒绝，只是延期。

## 何时检查 `.out-of-scope/`

在分诊第 1 步（收集上下文）时，读取 `.out-of-scope/` 下的所有文件。评估新 issue 时：

- 检查请求是否匹配已有的超范围概念
- 按概念相似度匹配，而非死板关键词：“夜间主题”就匹配 `dark-mode.md`
- 若命中，向维护者提示：“这与 `.out-of-scope/dark-mode.md` 类似。我们之前拒绝过，因为 [理由]。你现在还是同样的想法吗？”

维护者可以决定：

- **确认**：把新 issue 追加到现有文件的“历史请求”列表，然后关闭
- **重审**：删除或更新该超范围文件，让 issue 走正常分诊流程
- **不同意**：两者相关但实质不同，按正常分诊处理

## 何时写入 `.out-of-scope/`

仅当一个**特性请求（enhancement）**（而不是 bug）被以 `wontfix` *拒绝*时写入。这一规则对特性类 PR 同样适用：被拒绝的 PR 也记在这里，防止同样的需求换身代码卷土重来。

**不要**在某件事因为**已经实现**而以 `wontfix` 关闭时写入这里。那是已建成的功能，不是被拒绝的功能；记进这里会用假拒绝污染去重检查。此时只需在关闭评论里指明该功能已经存在的位置即可。

完整流程：

1. 维护者决定某个特性请求超出范围
2. 检查是否已存在匹配的 `.out-of-scope/` 文件
3. 若存在：将新 issue 追加到“历史请求”列表
4. 若不存在：新建文件，写明概念名、决策、理由以及第一条历史请求
5. 在 issue 下发表评论解释决定，并提及对应的 `.out-of-scope/` 文件
6. 贴上 `wontfix` 标签并关闭 issue

## 更新或移除超范围文件

如果维护者对之前拒绝的概念改变了主意：

- 删除对应的 `.out-of-scope/` 文件
- 无需重新打开旧 issue；它们只是历史记录
- 触发本次重审的新 issue 走正常分诊流程
