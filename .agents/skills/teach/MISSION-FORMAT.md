# MISSION.md 格式规范

`MISSION.md` 位于工作区根目录，记录用户学习该主题的*根本原因*。每一次教学决策（接下来教什么、引入哪些资源、设计什么练习）都应能追溯回这份文档。

## 模板

```md
# 学习使命：{主题}

## 为什么学
{1–3 句话。用户追求的具体现实目标。掌握这项技能后，他的生活或工作会发生什么改变？避免“为了理解 X”这类抽象表述，追问背后的实际成果。}

## 成功的样子
- {用户将能做到的具体、可观察的事情}
- {另一件具体事情}
- {……}

## 约束条件
- {时间、预算、已有安排、学习偏好等任何限制方案的条件}

## 范围之外
- {用户明确表示当前不想追逐的相邻主题，用于保护最近发展区}
```

## 规则

- **每个工作区一个使命。** 如果用户想学两件不相关的事，就建两个工作区。
- **具体胜于抽象。** “十月前跑完半程马拉松”胜过“变得更健康”；“给团队交付一个 Rust CLI”胜过“学习 Rust”。
- **追问模糊之处。** 如果用户说不清为什么学，先访谈清楚再落笔。一个糟糕的使命比没有使命更糟。
- **现实变化时及时修订。** 使命会变。当用户目标转移时更新本文件，不要让过时的使命误导后续会话。
- **保持简短。** 如果 `MISSION.md` 超过一屏，它就已经从指南针变成了计划表。
