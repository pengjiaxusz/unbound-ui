# 学习记录（Learning Record）格式规范

学习记录存放在 `./learning-records/` 下，按顺序编号：`0001-slug.md`、`0002-slug.md` 等。采用懒创建：仅在写入第一条记录时才创建该目录。

它们相当于教学领域中的架构决策记录（ADR）：记录非显而易见的收获、关键洞见以及用户明确声明过的已有基础，用于指引后续会话，并据此计算最近发展区（ZPD）。

## 模板

```md
# {学到或确认的内容的简短标题}

{1–3 句话：学到了什么（或确认了什么已有知识），以及它为何会改变后续会话的教学安排。}
```

全部格式就是这么简单。一条学习记录完全可以只有一段话。价值在于记录*这件事现在已经掌握*以及*它为什么影响接下来教什么*，而不是填满各种固定栏目。

## 可选小节

仅在确实增加价值时包含，大多数记录不需要：

- **Status** 前置状态（`active | superseded by LR-NNNN`）：当早期理解被证明有误并被替代时很有用。
- **Evidence**：用户是如何证明已理解的（回答了什么问题、完成了什么练习、引用了什么过往经验），当结论可能需要复核时有用。
- **Implications**：这为后续会话解锁了什么或排除了什么，在影响不直观时值得记录。

## 编号

扫描 `./learning-records/` 下现有的最大编号并加一。

## 何时写入学习记录

满足以下任一条件时写入：

1. **用户展示了对非平凡概念的真正理解**：不仅仅是听过，而是有证据表明能正确运用。这会抬高后续教学的起点。
2. **用户披露了先验知识**：“我已经懂 X 了。”记录下来以免后续重复教学，同时记下对方声称的*掌握深度*。
3. **纠正了一个误解**：用户原本持有错误认知，现在明白了原因。这类记录价值极高，能预测相关主题的后续卡点。
4. **学习目标因学习过程而发生转向**：用户发现自己真正关心的方向与最初不同。需与 [[MISSION.md]] 交叉链接并同步更新。

### 哪些情况*不符合*记录条件

- 仅仅“讲过”的内容。覆盖过不等于学会了，要等待理解证据。
- 已经在 [[GLOSSARY.md]] 中精炼收录的术语定义。不要重复。
- 逐次会话的流水账日志。学习记录不是日记，而是决策级的洞见。

## 替代（Supersession）

当后续记录推翻了早期记录（用户理解加深或纠正了偏差），不要删除旧记录，而是在旧记录上标记 `Status: superseded by LR-NNNN`。理解演变的轨迹本身也是宝贵信号。
