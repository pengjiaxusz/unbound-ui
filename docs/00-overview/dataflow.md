## 各级脏标记如何分流

状态演进层是整条链路的分叉点。三个级别的脏变走三条完全不同的路径，成本相差
三个数量级：

| 级别 | 触发条件 | 路径 | 排版开销 |
| :--- | :--- | :--- | :--- |
| Level 1 | 颜色、透明度、变换 | 直写瞬态环或 Compute Scatter 修补持久池 | 零 |
| Level 2 | 隔离边界内布局变化 | 只重算最近的 `RelayoutBoundary` 子树 | 局部 |
| Level 3 | 窗口尺寸或顶层分割线变化 | 全量重排 | 全局 |

详见[增量排版引擎](../02-ui/layout.md)。

## 增量修补的提交语义

"只传脏切片"成立的前提是**池里的内容与差分基线一致**。差分基线在每次重建时
前移，无论这一帧是否真的画了出来；因此一帧被丢掉时，池就落在了基线后面。

这条纪律落到两处：

- 渲染器把上传代次分成"已暂存"与"已提交"，只在提交成功之后才推进已提交值
  （`unbound_gpu::UploadGeneration`）。
- 宿主记着上一帧是否被丢；被丢过时，下一次上传强制全量，把池拉回基线。

同样地，呈现尺寸只有一个来源：已提交的交换链尺寸。布局视口与 UI 相机都从
它推导，窗口尺寸只用来判断要不要重建交换链。详见
[窗口呈现](../01-graphics/window-presentation.md)。

## 三条不经过 Reducer 的旁路

架构里有三条通路刻意绕过状态演进层，这是"每帧成本与场景规模无关"的关键：

1. **瞬态交互态**（框选虚线框、磁吸红线）直接写入帧瞬态环，不进入业务状态
   树，也不进 Undo 历史栈。见[交互编辑](../03-canvas/interaction.md)。
2. **主题切换**只改 4 KiB 颜色表，不触发排版、不重传实例。见
   [主题切换](../02-ui/theme-and-zoom.md)。
3. **摄像机平移缩放**只改 $16\text{B}$ Push Constants，画布实体在 GPU 侧
   原位解算相对坐标。见[分块锚定相对坐标](../03-canvas/chunk-coordinates.md)。
