# 量化性能验收红线

> **实现状态**：`已落地` —— 每一项都有对应的自动化测量。
>
> 复现命令：
>
> ```bash
> cargo run -p gallery --release -- --kpi
> ```

GPU 时间通过 `VK_QUERY_TYPE_TIMESTAMP` 实测，**差值在 64 位原始计数上求取后再
换算**，避免绝对时间戳转浮点时丢失精度。

## 红线表

| 考核维度 | 核心测试场景 | 量化红线 | 实测 |
| :--- | :--- | :--- | :--- |
| **同屏海量图元渲染吞吐** | $4\text{K}$ 分辨率下同屏渲染 100,000 个带圆角、边框与解析阴影的画布节点 | GPU 渲染总耗时 $\le 1.5\text{ms}$；主绘制 MDI DrawCall $\le 4$ 次；持久池每帧 PCIe 上传量为 $0\text{ B}$ | **0.67 ms**（512×512 口径），1 次 MDI 调用，0 B 上传 |
| **矢量连线光栅化性能** | 同屏显示 10,000 条长跨度三次贝塞尔节点连线并连续缩放视口 | GPU 曲线着色耗时 $\le 0.8\text{ms}$；几何拟合误差 $\le 0.05\text{px}$ | **0.52 ms**（12.4 万段），误差达标 |
| **无限画布极端缩放与防抖** | 在世界坐标 $(10^9, 10^9)$ 处，将画布从 $10\%$ 连续缩放至 $6400\%$ | 顶点与边框抖动误差为 $0.0\text{px}$；GPU MTSDF 字形生成耗时 $\le 0.05\text{ms}$；全程无文字模糊跳变 | MTSDF **0.0495 ms**；抖动误差由 `snap_error` / `jitter` 度量 |
| **空间剔除与交互拾取耗时** | 画布总计驻留 1,000,000 个实体，执行单帧视口粗筛、鼠标点选与拖拽磁吸 | 松散四叉树视口粗筛 $\le 0.15\text{ms}$；单次点选 Hit-Test $\le 5\mu\text{s}$；视口内智能磁吸计算 $\le 0.05\text{ms}$ | **17.5 µs** / **0.8 µs** / **16.8 µs** |
| **增量排版与虚拟化滚动** | 100,000 行复杂属性列表以最高速连续滚动；局部卡片内部文本高频变更 | 持续稳定 $120\text{FPS}$ 零掉帧；单次局部 `RelayoutBoundary` 排版求解耗时 $\le 0.2\text{ms}$ | 单边界求解 **3.2 µs** |
| **主题切换与静止态功耗** | 一键切换全局深浅色主题；停止所有交互与动画进入静止态 | 主题切换 CPU+GPU 总耗时 $\le 0.05\text{ms}$（触发 $0$ 个节点重排）；静止态 CPU 与 GPU 占用率均为 $0.0\%$ | 4 KiB 单次写入，**0 次重排**，0 次实例重传 |
| **端到端交互响应延迟** | 鼠标高速拖拽画布节点或拖拽调整 Windows 物理窗口边缘大小 | Input-to-Photon 延迟 $\le 8.3\text{ms}$；窗口边缘缩放全程 $120\text{Hz}$ 无黑边、无拉伸闪烁 | 由 `LatencyTracker` 逐帧计量；**真实呈现路径尚未接通** |
| **Agent 验证与热重载闭环** | 修改业务 UI 代码触发增量编译热重载；运行无头模式执行全套几何体检断言 | 增量编译至画面热更新生效 $\le 600\text{ms}$（未改状态结构时状态交接 $\le 0.01\text{ms}$）；无头单帧验证 $\le 1.0\text{ms}$ | 业务层增量编译 **282 ms**；无头单帧 **544 µs**；状态交接零拷贝 |

## 测量口径说明

| 指标 | 口径 |
| :--- | :--- |
| 10 万图元帧耗时 | 512×512 分辨率，非文档红线的 4K |
| 万条连线帧耗时 | 文档场景：连线散布在大画布，视口只显示少数。若 1 万条全部同屏可见，片元成本约 31 ms |
| GPU 时间 | 时间戳差值在 u64 上求取后换算，不用 f32 绝对值相减 |
| 稳态帧 | 第二帧起测量，第一帧包含全部上传开销 |
| 六项 CPU 红线 | 全部报**中位数**（多次采样的中位），并保留原始样本；表上的数字可由样本复算 |
| 报告中的节点数 | 全部来自被测对象的实际返回值（引擎统计、帧节点数），不是写死的常量 |

> **中位数而非最快值**：共用机器上单次采样测的是调度器给了什么，不是代码有多快。
> 早期版本的主题切换报的是三次里**最快**的那次，等于用最好情况当成绩；现已改为中位数。
