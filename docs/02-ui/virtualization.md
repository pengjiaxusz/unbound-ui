# 视口虚拟化

> **实现状态**：`已落地`
>
> | | |
> | :--- | :--- |
> | **源码** | `crates/unbound-world/src/virtualize.rs` |
> | **关键类型** | `VirtualList`、`VirtualTree`、`VirtualGrid`、`TreeRow`、`WindowUpdate` |

针对包含 $10$ 万级条目的图层树、资产网格或日志面板，框架核心层内置
`VirtualList`、`VirtualTree` 与 `VirtualGrid` 容器协议。

## 环形槽位复用

仅在 `SlotMap` 与 Taffy 树中实例化当前视口可见区域加上下各 $1$ 屏缓冲区的
节点（通常恒定在 $60 \sim 120$ 个实体）。

滚动发生时：

- **未跨越单行高度阈值**：仅更新 GPU 端 `Transform` 平移偏移量（耗时为 $0$）。
- **跨越行高阈值**：将滑出视口顶部的节点槽位原地复用于底部新进入视口的数据
  项。

保证 $10$ 万行列表 $120\text{FPS}$ 极速滚动零内存分配。

## 三种容器的差异

| 容器 | 行高 | 可见性判定 | 复用单位 |
| :--- | :--- | :--- | :--- |
| `VirtualList` | 固定 | 区间重叠 | 整行 |
| `VirtualTree` | 可变 | 展开路径 + 区间 | 节点槽位 |
| `VirtualGrid` | 固定 | 二维区间重叠 | 单元格 |

`TreeRow` 描述树中一行的可见区间与层级缩进，`WindowUpdate` 描述一次滚动
导致的可见窗口变化——两者都是纯数据，可以直接喂给 GPU 做增量更新。

## 与世界状态树的耦合

虚拟化容器不是独立的控件，而是世界状态树的一种节点类型。它只持有**窗口
内的**节点，窗口外的数据按需从数据源拉取。这保证 `SlotMap` 的大小与数据总量
解耦。
