# 文本渲染控制台规格说明（Spec）

- **状态**：`ready-for-agent`
- **关联 ADR**：ADR 0013（文本抗锯齿仅灰度）
- **领域词汇基准**：`GLOSSARY.md`

---

## 问题陈述（Problem Statement）

展台已经能验证主题、缩放、后景、双拼方案与虚拟化，唯独**文本渲染自身的参数没有任何运行期出口**。

具体表现为四个痛点：

1. **后端差异只能靠重启验证**：`RasterBackend` 在 `GlyphCache` 构造时确定，唯一的运行期入口是环境变量 `UNBOUND_TEXT_BACKEND`。想比较 DirectWrite 与 swash 的同一段文字，必须改环境变量、重启进程、再用肉眼回忆上一版长什么样。
2. **更深的开关根本没有出口**：亚像素相位档位、距离场、Emoji 的来源与呈现路径，全部编译期固定。排查"这个字形为什么边缘发毛"时无法做界面上的二分定位，只能改代码。
3. **能力边界不可见**：框架对外声明"灰度抗锯齿""八相位""彩色 Emoji 走 swash"，但展台上没有一处能看到这些声明的实际证据，也无法区分"没实现"和"我没找到开关"。
4. **已有开关散落且无失效策略**：`snap_phases`、`use_sdf`、`sdf_spread` 是 `GlyphCache` 的公开字段，谁改谁负责清缓存。运行期改动若忘记让图集失效，旧位图会残留在新配置下，产生"改了没生效"或"字形串味"的假象。

---

## 解决方案（Solution）

在展台新增一个**文本渲染**页面，形态为左侧参数面板 + 右侧实时预览 + 底部实际生效状态栏。

1. **参数按六组收纳**：字体、排版、像素、距离场、合成、Emoji。每组可折叠，折叠状态随页面保存。
2. **参数分三类呈现**，而不是一律做成可选：
   - **可切换**：当前后端真的支持，切换后立即生效；
   - **不可用**：灰化，悬停给出原因（不是"暂不支持"，而是具体到"两个后端都不提供 hinting"）；
   - **本轮未实现**：灰化并标注"未实现"，与"不可用"区分开。
3. **配置是单一纯值结构**，跨页面保持。其中的字段分两类，作用域不同：

   | 类别 | 字段 | 作用域 |
   | :--- | :--- | :--- |
   | **预览样式** | 家族、字重、字号、斜体 | 只作用于预览样本。其他页面的字体不变，以便对照时参照物固定 |
   | **渲染策略** | 排版、像素、距离场、合成、Emoji | 全局生效。切换页面后其他页面的文本随之改变，这是刻意的 |

   划这条界的理由：面板要做的是"同一段文字在不同渲染策略下长什么样"的对照实验。如果字体也跟着变，两个变量同时动，肉眼看到的差异就归因不了。
4. **状态栏读实际生效值**，不是用户选择值。后端回退、Emoji 路径回退、回退次数与最近一次原因都在这里可见。
5. **预设提供四个起点**：WinUI 原生、跨平台一致、像素风、自定义。预设是取值组合，不是代码分支；手动改动任意一项即转为"自定义"。

## 用户故事（User Stories）

1. 作为框架开发者，我希望在同一页面切换 DirectWrite 与 swash，以便用肉眼比较同一段文字的边缘灰阶，而不必改环境变量并重启。
2. 作为框架开发者，我希望切换亚像素相位档位（8 / 4 / 1），以便验证相位缓存是否真的改善了小字号字距的均匀度。
3. 作为框架开发者，我希望面板明确告诉我"网格拟合在当前实现下不可选"，以便不再怀疑是自己没找到开关。
4. 作为框架开发者，我希望不可用的选项被禁用并给出具体原因，以便不必逐个试错。
5. 作为框架开发者，我希望状态栏显示**实际生效**的后端与相位数，以便区分"我选了"和"真的生效了"。
6. 作为框架开发者，我希望状态栏显示 Emoji 的实际路径（彩色 swash / 单色 R8 / 回退），以便确认某个 Emoji 没有偷偷走另一条路。
7. 作为框架开发者，我希望看到回退计数与最近一次回退原因，以便定位"某个字符显示成方块"这类问题。
8. 作为框架开发者，我希望选择一个预设就填好一组已知可用的参数，以便快速进入对照基线。
9. 作为框架开发者，我希望手动改动任意一项后预设标签自动变为"自定义"，以便知道当前不在任何预设上。
10. 作为框架开发者，我希望切换后端后旧字形不会残留，以便不会把缓存失效 bug 误判成渲染差异。
11. 作为框架开发者，我希望设置对象在切换页面后保持，其中渲染策略在其他页面同样生效，以便验证同一策略下不同页面的文本表现一致。
12. 作为框架开发者，我希望预览样式（家族、字重、字号、斜体）不改动其他页面的字体、排版语义（断行、连字、字距、行高）只清塑形缓存，以便对照实验时参照物固定，且调整这些项不会重建整张图集。
13. 作为框架开发者，我希望 Emoji 的"来源""呈现""光栅器""调色板""失败回退"是五个独立维度，以便分别验证字体来源与光栅器这两条正交的轴。
14. 作为框架开发者，我希望选择"单色"时状态栏注明它走 R8 图集并用文字色染色，以便确认没有偷偷走彩色路径。
15. 作为展台访客，我希望这些控件可以用键盘操作，以便不依赖鼠标。
16. 作为展台访客，我希望深色主题下面板与状态栏仍然清晰可读。
17. 作为框架开发者，我希望面板的能力查询与框架公开的能力声明同源，以便不会出现"面板能选、集成方却用不了"的分裂。

## 实现决策（Implementation Decisions）

### 接缝

只开一个接缝：**纯值配置进、只读报告出**。

- `TextRenderSettings`：可序列化的纯值结构，承载全部可切换项。这是唯一允许改动渲染行为的入口。
- `TextRenderReport`：只读快照，包含实际生效的后端、相位数、Emoji 路径、回退计数与最近一次回退原因。
- `TextCapabilities`：按平台、后端实现状态与所选字体的实际表（COLR / CPAL / CBDT / sbix / SVG）合成，回答"这一项现在能不能选"。

展厅只读 `capabilities`、写 `settings`、读 `report`，**不得直接操作字形缓存**。现有 `RasterBackend`、`snap_phases`、`use_sdf`、`sdf_spread` 等散落字段收敛进 `TextRenderSettings`，保留旧入口作为 `#[deprecated]` 适配层或直接迁移调用方。

### 配置应用与失效粒度

宿主在每帧开始比对配置指纹，变化时调用一次应用函数。应用函数内部做字段级差异比较，按三档决定失效范围：

| 影响面 | 字段 | 作用域 | 失效动作 |
| :--- | :--- | :--- | :--- |
| 预览样式 | 家族、字重、字号、斜体 | 仅预览样本 | 不清任何缓存，下帧按新样式塑形 |
| 排版语义 | 塑形器、断行、双向、连字、字距、行高 | 全局 | 清塑形缓存与换行缓存，**不清**字形位图 |
| 位图内容 | 光栅器、相位档位、距离场、Emoji 路径 | 全局 | 清字形缓存 + 两套图集 + 待上传队列，整表重建 |

分档依据是"会不会改变已有产物的含义"，不是"改动大不大"：字距与行高改变换行位置与行数，属于排版语义；字号虽然也改变布局，但字形键本身就含字号，新旧条目天然互不干扰，因此不需要清空。

第三档必须是整表清空，不允许"只清 R8 保留 RGBA"这类部分失效——图集键不含后端维度，部分清理会让旧后端的位图在新后端下被命中。

### 相位档位

`SUBPIXEL_PHASES` 从常量改为由配置派生。图集键的相位掩码随档位变化：8 档掩 `0b111`、4 档掩 `0b11`、1 档固定为 0 且不再参与键。切换档位属于位图级失效。

### 明确不实现的项

面板必须**如实呈现**下列项不可用，而不是留一个点了没反应的开关：

- **网格拟合（hinting）**：DirectWrite 侧固定 `GRID_FIT_MODE_DISABLED`，因为网格拟合会把八相位重新量化到整像素、与相位缓存直接冲突；swash 的 zeno 光栅器本身不做 hinting。该项只有"关"可选。
- **子像素抗锯齿（RGB / BGR）**：ADR 0013 已定为仅灰度。两档灰化，原因写"与透明图层、任意后景混合互斥"。
- **MTSDF**：距离场选项目前只有"关 / SDF"，MTSDF 档灰化，原因写"管线未接线"。

### Emoji 五维

- **来源**：系统 / 内置 / 网格。本轮只有"系统"可选——"内置"需要打包字体文件（分发与许可），"网格"需要自带图集与码位映射，两项均在范围之外，标为未实现并灰化。选"网格"时其余四项全部隐藏（图片已是最终像素，没有光栅化环节），该规则在网格可用后才实际生效。
- **呈现**：彩色 / 单色。单色走 `Atlas_R8`、以文字色染色，`ResolvedGlyph.color == false`。
- **光栅器**：跟随正文 / DirectWrite / swash。`彩色 + DirectWrite` 当前能力查询返回不支持，见"待决策"。
- **调色板**：跟随主题 / 浅色 / 深色。仅在"彩色 + DirectWrite"下可见。
- **失败回退**：静默换 swash / 降级单色 / 占位框。仅在"彩色 + DirectWrite"下可见。

缓存键需要新增 `paletteIndex` 与 Emoji 呈现模式两个维度，否则深色主题下会命中浅色调色板的旧条目。

### 能力查询

`TextCapabilities` 是唯一的能力真相源，面板不得自行判断平台。每个能力回答**三态**：

| 状态 | 含义 | 面板表现 |
| :--- | :--- | :--- |
| 可用 | 已编译且当前环境支持 | 可选 |
| 不可用 | 已编译，但环境不满足（如字体缺 COLR 表） | 灰化 + 环境原因 |
| 未编译 | 此构建未包含该后端或功能 | 灰化 + "此构建未包含" |

"未编译"必须与"不可用"分开：不加这一态，用户会把"这个二进制没编进来"误判成"系统设置有问题"。

它至少要回答：彩色字形是否可用、支持哪些彩色表、调色板数量、单色回退是否可用、可选相位档位、距离场是否可用、当前后端标识。

灰化规则（面板行为）。以下描述完整设计下的约束关系，其中涉及本轮不可用项的规则（第 1 条依赖网格来源、第 4 条依赖子像素抗锯齿）在对应项实现后才实际生效：

1. 来源 = 网格 → 呈现、光栅器、调色板、回退隐藏。
2. 呈现 = 单色 → 调色板、回退隐藏。
3. 光栅器 ≠ DirectWrite → 调色板、回退隐藏。
4. 抗锯齿 = 子像素 → 相位锁 1、图层锁不透明、光栅器锁 DirectWrite（三者物理绑定）。
5. 距离场 ≠ 关 → 抗锯齿锁灰度、相位锁 1。
6. 网格拟合在相位 > 1 时不出现在可选列表里。

### 预设

`WinUI 原生`：DirectWrite + 8 相位 + 灰度 + 线性混合 + Emoji DirectWrite 单色。
`跨平台一致`：swash + 灰度 + sRGB + Emoji swash 彩色。
`像素风`：DirectWrite + 1 相位 + 灰度 + 无距离场。
`自定义`：不主动选中，任何手动改动后自动落到这一项。

预设只写入设置值，不改变能力判定；预设里若含当前机器不可用的项，按能力查询的结果降级并在应用后由 `report` 反映。

### 状态栏

固定显示四项：正文实际后端、相位数、Emoji 实际路径、回退次数。回退次数可展开查看最近一次的回退原因（哪个簇、因为什么）。计数只在真正发生回退时递增，不因重绘或切页复位。

### 无障碍

每个控件有稳定节点标识与可读标签；分组标题是按钮语义，折叠状态进入语义树的展开状态位；灰化项仍需可聚焦，以便读屏用户能听到禁用原因。

## 测试决策（Testing Decisions）

**好测试的标准**：只断言外部可观察行为——给定一份配置，观察报告、图集状态与字形产物的变化；不直接断言内部字段、不锁定实现细节。

**现有先例**：

- `unbound-text` 中针对 DirectWrite 覆盖率的抗锯齿回归测试（断言中间灰占比阈值），是"用像素统计而非逐像素比对"的范式；
- `unbound-widgets` 的无头几何测试（不建 GPU 设备，直接断言发射结果），是"纯 CPU 可测"的范式。

**需要覆盖的用例**：

1. 切换后端后，字形缓存条目归零、待上传队列非空，且新一批位图的覆盖率分布与目标后端一致。
2. 只改字号时，图集不被清空（用待上传队列长度或图集代际断言）。
3. 相位档位为 4 时，同一字形最多产生 4 个不同的图集键；档位为 1 时只有 1 个。
4. 能力查询与面板灰化表驱动一致：caps 判定不支持时，对应控件必然禁用（同一张表驱动两边，避免两处真相）。
5. 预设应用后每项取值符合预设定义；手动改任意一项后预设标签变为"自定义"。
6. 单色 Emoji 产出的字形 `color == false` 且落在 R8 目标；彩色 Emoji 落在 RGBA 目标。
7. 回退计数单调递增，切页与重绘不使其复位。
8. 网格拟合控件在相位 > 1 时不出现在可选列表。

**不做的测试**：不为面板布局写像素快照；不为每个开关写一条用例（用表驱动覆盖组合）。

## 范围之外（Out of Scope）

- **彩色 Emoji 完整走 DirectWrite**（见下节待决策）。
- **贴图网格 Emoji 来源**：需要自带图集与码位映射表，属于资源打包议题。
- **内置 Emoji 字体打包**：字体文件的分发、许可与子集化不在本 spec 内。
- **真正的网格拟合 / hinting 实现**：两个后端都不提供，强行实现会与相位缓存冲突。
- **子像素抗锯齿**：ADR 0013 已排除。
- **MTSDF 管线接线**：`SdfPipeline` 尚未接入，不在本轮。
- **字干补偿与 gamma 校正**：本轮列为不可用，待后端能力具备后再开。

## 补充说明（Further Notes）

### 面板结构

左面板六组：字体（4 项，预览样式）、排版（6 项）、像素（6 项）、距离场（2 项）、合成（3 项）、Emoji（5 项）。右侧预览区展示一段中英混排、一行汉字、一行 Emoji 样本，以及当前样式的数值摘要。底部状态栏横跨整宽。

一屏放不下全部展开项，因此分组默认折叠状态需要持久化，不能每次进入页面都重置。

### 关于"面板能选但集成方用不了"

面板与框架公开的能力声明必须同源。若面板能选某个组合，集成方在同样平台上调用公开 API 也必须能得到同样结果；反过来，框架文档里声明不支持的能力，面板必须灰化。这条约束比面板本身更重要。

## 待决策：彩色 Emoji 完整走 DirectWrite

**状态**：`deferred`，等其余开关全部落地后再评估。

### 目标

让彩色 Emoji 也不再依赖 swash，使 DirectWrite 成为唯一的光栅化后端，从而砍掉一条后端分支、一套缓存失效路径与一处平台差异。

### 需要实现的内容

1. 用 `TranslateColorGlyphRun` 把一次字形簇拆成有序的层，每层携带 `runColor` 与调色板索引；
2. 对每个矢量层复用现有的覆盖率分析，按 `runColor` 染色后做 over 合成；
3. 对位图层（CBDT / PNG、JPEG）改用字形图像数据接口取原始字节，并接入解码器；
4. SVG 表层需要独立的 SVG 渲染器，评估结论是**放弃并回退**，不引入该依赖；
5. 合成结果的边界框取各层并集，并保留现有 padding。

### 三个已知约束

- **必须按簇处理**：ZWJ 序列（家庭 Emoji）与肤色修饰符由多个码位组成一个视觉簇，不能沿用当前"单字形独立光栅化"的假设。这一条需要单开一条簇级入口，是整件事里最容易出错的部分。
- **调色板必须进缓存键**：部分彩色字体带浅色 / 深色两套调色板，缺失该维度会在深色主题下命中错误条目且长期不自愈。
- **纯位图字体没有轮廓**：以 CBDT 为主的字体其 `glyf` 表为空，覆盖率分析会返回空白。启用前必须探测轮廓表是否存在，不存在则直接回退。

### 成本与收益判断

- 成本：三百到五百行新增代码，三到五个工作日，主要集中在层合成、簇级入口与回退路径。
- 收益：**不是画质**。彩色路径下两个后端解析的是同一份彩色表与同一套调色板，差异只存在于轮廓转覆盖率这一步，而 Emoji 是大色块、无细笔画，该差异肉眼不可辨。
- 真实收益是**依赖收敛**：少一个后端、少一套失效逻辑、少一处平台差异。

### 触发条件

满足下列任一条件时重新评估，否则维持 `deferred`：

1. swash 成为工作区里唯一无法替换的第三方光栅化依赖，且该依赖带来实际的维护或安全问题；
2. 需要支持仅提供 SVG 表的彩色字体（当前 swash 无法渲染该表）；
3. 跨平台策略变化，需要在非 Windows 平台也提供与 DirectWrite 等价的彩色路径。

### 在此之前的面板行为

`呈现 = 彩色` 且 `光栅器 = DirectWrite` 的组合在能力查询中返回"未实现"，UI 灰化并在悬停提示中写明"需要层遍历，见待决策"。不得让它可选，也不得在选中后静默降级而不告知——那会让状态栏的"实际生效"失去意义。
