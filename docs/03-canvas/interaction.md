## 瞬态与持久状态严格物理隔离

框选虚线框、鼠标悬浮高亮框、实时对齐磁吸红线、连接线拖拽预览属于**瞬态状态
(Ephemeral State)**，在输入处理阶段直接生成图元写入帧瞬态环（Transient Ring
Buffer），**绝不污染 Reducer 业务状态树与 Undo 历史栈**。

这条边界让"按住鼠标移动"不会在撤销栈里留下一串记录——用户期望撤销的是"这次
拖动"这一个动作，不是中间上百次鼠标移动。

## 视口级智能磁吸计算

实体拖拽移动时，利用松散四叉树仅检索当前屏幕视口及外扩 $64\text{px}$ 范围内的
候选图元。

若视口内图元密集，按面积与距离优先级**截断前 128 个显著对象**，构建 X/Y 轴向
一维有序区间表，在小于 $0.05\text{ms}$ 内完成：

- 左 / 中 / 右、顶 / 中 / 底边缘对齐
- 等间距（Equal Spacing）判定

屏幕空间距离小于或等于 $5\text{px}$ 时触发坐标吸附修正并生成瞬态红线。

### 截断策略的意义

不截断的话，候选集会随视口内实体数线性增长，磁吸耗时随之退化。截断到 128 个
显著对象后，耗时变成常数——这是又一个"与规模无关"的点。

`Snapper::retained_candidates()` 暴露实际保留的候选数，便于诊断。

## 原子事务撤销/重做与输入合并

复杂拖拽交互开始时派发 `BeginTransaction`，拖拽期间高频派发轻量
`UpdateTransaction`（仅原地修改当前活跃快照，**不压入历史栈**），释放鼠标时
派发 `CommitTransaction`。

```
begin(kind, label)  ──►  update(...) × N  ──►  commit()
   │                      只改活跃事务              │
   └──► push 到历史栈 ◄──────────────────────────┘
```

### 文本输入合并

针对连续键盘输入，基于时间窗口（如 $500\text{ms}$）与词边界（空格/标点/换行）
自动合并连续字符变更，结合 COW 结构共享，使百万级节点画布的单步 Undo 快照
内存增量恒定在数 KB 以内。

### 补丁而非快照

`UndoStack` 存的是 `Edit` 补丁（几何增量、文本区间），不是场景副本。每个
`Edit` 有 `inverted()` 生成反向补丁，因此重做不需要重新记录。

| 指标 | 值 |
| :--- | ---: |
| 单个 Edit 内存 | `Edit::bytes()` 可查，通常数十字节 |
| 单个事务内存 | `Transaction::bytes()` 可查 |
| 撤销栈深度 | 由 `UndoStack::new(limit)` 限定 |
