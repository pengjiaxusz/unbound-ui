# 布局与视图树

## 1. 核心问题与定位
声明式 UI 写起来直观，但如果每帧都销毁并重建整棵布局树、从根节点重新求解所有尺寸，面对长列表或复杂工作台时就会严重掉帧。本模块负责维护跨帧保留的逻辑树、局部状态挂载以及增量布局求解。

## 2. 核心概念模型
- **保留模式语义世界**：虽然开发者以声明式方式描述当前帧界面，但底层通过稳定语义键在帧间复用已有节点，精准识别节点的新增、更新与卸载。
- **重排边界**：一种隔离标记，用于声明“内部尺寸变化不会影响外部容器大小”。它是阻断脏标记无限向上冒泡的核心屏障。
- **视口虚拟化**：对于包含成千上万行数据的列表、树或表格，只为当前可见视口（外加少量缓冲区）内的条目创建和求解布局节点。

## 3. 增量排版与虚拟化流程

```mermaid
flowchart LR
    View["声明式视图描述"] --> Reconcile["按稳定键对齐保留节点树"]
    Reconcile --> Dirty["收集脏节点并向上回溯"]
    Dirty --> Stop["遇到重排边界即截断"]
    Stop --> Solve["并行求解各独立脏子树"]
    Solve --> Emit["输出世界坐标矩形与局部状态"]
```

## 4. 关键设计取舍
- **基于稳定键的协调复用**：要求可交互或带状态的节点提供稳定标识，避免依赖脆弱的数组下标顺序，从而确保局部状态（如滚动偏移、输入框光标、展开折叠态）在列表重排时不丢失。
- **文本固有尺寸按需测量**：普通容器走标准弹性/网格约束；只有包含动态文本或自定义固有尺寸的叶子节点才触发文本整形测算，避免无谓的字体测量开销。

## 5. 边界与不变量
- **重排边界必须自洽**：被标记为重排边界的容器必须拥有确定尺寸（或完全由外部约束决定），否则内部变化将无法正确对外隔离。
- **跳帧不触发卸载**：当一帧因无变更而跳过视图重建时，已有局部状态键必须全部保留，严禁误判为“未渲染”而清理卸载。
- **渲染即视为挂载**：重建帧内每个被 `ensure_state` 触及的控件键都必须标记为本帧已访问（即使状态早已存在），否则帧末的挂载差集会把仍在渲染的控件判为卸载并丢弃其状态，表现为控件状态隔帧重置。
