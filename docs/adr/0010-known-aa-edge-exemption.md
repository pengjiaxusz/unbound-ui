# ADR 0010：纯边缘抗锯齿差异经视觉复核后可判 `known-aa`，不按失败处理

- 状态：已修订（2026-11-22，命名与适用范围由 ADR 0028 泛化为通用豁免；门禁原则不变）
- 日期：2026-11-19
- 关联：ADR 0008（ROI 门禁与控件分类）、ADR 0009（有效性三态）

## 背景

`InfoBadge` 与 `RatingControl` 的 8 个用例（normal/disabled × light/dark）在几何
与整体颜色已对齐的前提下，始终差 1px：

- 两侧内容包围盒逐边完全一致（`InfoBadge` 为 `{16,16,31,31}`，`RatingControl`
  为 `{16,24,127,39}`），固有尺寸门禁也通过；
- 有效对比区 ΔE2000 均值在 0.9–1.7 区间，整体颜色一致；
- 显著色差像素集中在圆周与星形轮廓的 1–2px 覆盖带上，占比 3%–10%，高于
  2% 的 `over_limit_ratio` 上限，但像素都落在内容包围盒的边缘。

逐像素放大复核确认差异来源：`InfoBadge` 的圆周边缘由 WinUI 3 与 DirectWrite
不同的 AA 核光栅化，本框架用解析覆盖率场合成；`RatingControl` 的实心星在参考
截图中带 1px 对比色外描边（浅色更深、深色更亮），字形本身不含描边，需按八方向
偏移盖章补画。补齐描边后，剩余差异同样只落在轮廓覆盖带上。

## 决策

- **新增第四态 `known-aa`**：差分结果从 `pass / fail / invalid` 扩展为
  `pass / known-aa / fail / invalid`。`known-aa` 不计入失败，也不等同于 `pass`，
  在报告里单独计数。
- **豁免必须同时满足三条**，缺一不可：
  1. 用例名在显式的 `KNOWN_AA_CASES` 名单内；
  2. `bbox_matches()` 与 `intrinsic_matches()` 均通过，即几何与尺寸已对齐；
  3. `mean_de <= 2.0`，即整体颜色已一致。
- **先修结构性差异，再谈豁免**：复核时先看放大图判断差异是「轮廓覆盖采样」
  还是「少画/错色/偏移」。后者属于实现缺陷，必须修正（例如实心星的 1px 描边），
  不得用 `known-aa` 掩盖。
- **名单只收经视觉复核的用例**：新增条目前必须人工放大比对参考图与渲染图，
  确认剩余差异只在轮廓覆盖带内，并记录复核结论。名单不是阈值豁免，而是
  「已确认差异性质」的登记表。
- **不得滥用**：名单外的用例即使指标完全相同也判 `fail`；名单内但几何未对齐、
  或 `mean_de > 2.0`、或出现 `bbox` 之外的块状色差，同样判 `fail`。

## 备选方案

- **继续扫参直到 2% 以内**：实测会在 `p95_de` 与 `over_limit_ratio` 之间来回
  摆动，且不同主题需要不同参数，属于对 AA 核做过度拟合。
- **整体放宽 `over_limit_ratio` 到 4%**：会同时放过真正的漏画与错色，把门禁的
  灵敏度整体降一档，代价远大于收益。
- **自行实现与 WinUI 相同的 AA 核**：理论上可消除差异，但需要复刻其解析覆盖率
  与滤波窗，属于超出当前工单范围的渲染精度工程；若后续要做，应由独立工单推进
  并移除对应豁免。

## 后果

- `report.json` 的 `status` 增加 `known-aa`，`pass` 布尔值仍只对真通过为 `true`；
  展厅报告页按四态展示并单独统计豁免数。
- 批量摘要输出新增 `known-aa=N`，失败明细列表不再展示 `known-aa` 用例。
- 豁免名单是显式白名单，新增控件或状态不会自动获得豁免；一旦 AA 核升级使差异
  消失，用例会自然回到 `pass`，名单条目可在复跑后删除。
- 当前登记 8 例：`InfoBadge` 与 `RatingControl` 的 normal/disabled × light/dark。
