# ADR 0028：豁免机制泛化——从「known-aa 抗锯齿豁免」到带理由的通用豁免登记

- 状态：已采纳
- 日期：2026-11-22
- 关联：ADR 0010（known-aa 边缘豁免，本 ADR 修订其命名与适用范围）、
  ADR 0026 / 0027（parity 矩阵与命令族）

## 背景

ADR 0010 引入的第四态 `known-aa` 仅针对「纯边缘抗锯齿差异」。实践中发现两个问题：

1. **命名过窄**：豁免的真实含义是「结构性差异已修复、剩余差异经人工复核
   确认无法通过参数对齐」，剩余差异不一定只是抗锯齿——可能是字形引擎的
   gamma 覆盖率混合模型（DirectWrite 特有）、纹理合成路径的 AA 核差异等。
   继续叫「抗锯齿豁免」会误导复核者以为只允许轮廓覆盖差。
2. **死磕参数的边际收益为负**：以 RatingControl 为例，为把轮廓残差从 5.7%
   压到 2% 以内，先后尝试了亚像素盖章、放大字形垫底、改权重等方案，多数
   反而恶化指标（p95 从 6 升到 25）。指标已达 mean ≤ 2.0 的用例继续调参
   得不偿失。

同期取得的进展证明「先修结构性差异」的原则仍然有效：

- `InfoBadge` 四态：圆盘覆盖率场引入 gamma（R=7.6 / F=0.6 / γ=0.4，两主题
  联合拟合一致）后 **全部真实通过**，已从豁免名单移除；
- `RatingControl` disabled 态描边色 token 由 172 修正为实测的 211。

## 决策

- **改名为通用豁免**：`KNOWN_AA_CASES` → `EXEMPT_CASES`（条目结构
  `ExemptCase { name, reason }`），`CaseStatus::KnownAa` → `CaseStatus::Exempt`，
  报告状态字符串 `known-aa` → `exempt`（读取旧报告时兼容 `known-aa`）。
- **每条豁免必须写 `reason`**：说明已修复什么、剩余差异的性质为何无法对齐。
  空理由的条目不得合入。
- **门禁不放宽**：豁免仍要求包围盒 ±1px、固有尺寸 ±1px、
  `mean_de <= EXEMPT_MEAN_LIMIT`（2.0）三条同时满足，维持 ADR 0010 的
  「先修结构性差异，再谈豁免」与「不得滥用」原则。
- **大差不差即登记**：指标满足上述三条但 `over_limit_ratio` / `p95` 未达标、
  且复核确认剩余差异属于字形/边缘混合模型差异的用例，直接登记豁免，
  不再调参。
- **InfoBadge 四态移出名单**：结构性修复后已真实通过。

## 影响

- `report.json` 的 `status` 字段出现 `exempt`（旧文件为 `known-aa`，
  报告页两种都能解析）；
- 终端摘要与展厅报告页标签改为「豁免 / exempt」；
- 后续若字形引擎引入 gamma 混合等能力，应重新评估名单，能转正即移出。
