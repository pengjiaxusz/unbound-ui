# ADR 0008：控件像素差分采用拼版采集、有效对比区四重门禁与双端指纹缓存

- 状态：已采纳
- 日期：2026-11-18

## 背景

早期试点差分流程存在三处随控件与状态规模扩张而恶化的缺陷：

1. **吞吐瓶颈**：参考宿主逐个用例切换内容并等待 `350ms` 动画收敛，本框架侧每渲染一个用例都重新创建并销毁一次 Vulkan 设备、渲染器与字形图集。当用例维度扩展到「控件 × 状态 × 主题 × 后景」时，采集与渲染耗时呈线性爆炸。
2. **背景稀释假阳性与固有尺寸掩盖**：画布固定为 `420×160`，而多数控件仅占画布不足 10% 的面积。全图统计 $\Delta E2000$ 均值与 `p99` 时，90% 以上完全一致的背景像素将均值稀释十余倍，导致肉眼明显不符的控件依然判定为通过；同时本框架渲染时直接使用参考 JSON 的 `controlBounds` 强行布局，掩盖了本框架控件默认固有尺寸（如默认高 `36px` vs WinUI 标准 `32px`）的偏差。
3. **重复无增量计算**：跨次运行缺少缓存机制，即使 SDK 版本、用例规格或控件源码分毫未动，仍会全量重跑截图与差分。

此外，控件在云母、亚克力等后景材质下的半透明叠色表现需要纳入自动化对比，但真实桌面 DWM 屏幕捕获受壁纸与窗口位置影响（见 ADR 0007），无法直接充当大规模控件级回归门禁。

## 决策

- **按「控件 × 主题 × 后景」为单位生成状态拼版图集并切出紧凑单图**：参考宿主在批量模式下将该控件支持的所有状态排入同一张网格拼版（Contact Sheet），单次等待 `350ms` 动画收敛、单次 `RenderTargetBitmap` 导出，随后按各槽位 `controlBounds` 外扩 `16px` 出血位裁剪出紧凑单图与独立 JSON。本框架侧在整个批量会话内全局复用同一个 GPU 设备、渲染器与字形图集实例，并支持对单帧尺寸动态调整。
- **有效对比区（ROI）四重门禁**：差分器取 `union(reference_bbox, ours_bbox, controlBounds)` 外扩 `2px` 作为**有效对比区**，仅对该区域内的像素统计色差，并执行四重门禁：
  1. **包围盒对齐（`bbox_matches`）**：内容包围盒逐边误差 `≤ 1px`；
  2. **固有尺寸对齐（`intrinsic_matches`）**：在未强制指定固定宽高的自由维度上，本框架 `intrinsic` 尺寸与参考边界误差 `≤ 1px`；
  3. **ROI 色差均值与分位数**：`roi_mean_de <= 1.5` 且 `roi_p95_de <= 4.0`；
  4. **显著色差像素占比（`over_limit_ratio`）**：ROI 内 $\Delta E2000 > 5.0$ 的像素占比 `≤ 2%`（0.02），防止圆角、描边或局部图标漏画被面积均值掩盖。
- **双端用例指纹缓存**：引入清单级缓存校验。参考侧以 `(windowsAppSdkVersion, osBuildNumber, rasterizationScale, caseKey, specHash)` 为指纹；本框架侧以 `(caseKey, rasterScale, controlBounds, widgetSourceHash)` 为指纹（覆盖对应控件源码、基础图元与主题调色板哈希）。指纹命中且磁盘产物完好时直接跳过采集或重绘。
- **合成底板预留后景维度**：用例键扩展为 `(control, state, theme, backdrop)` 四元组（当前默认激活 `solid` 纯色基准面，后续待云母完工后解锁 `mica`、`mica_alt`、`acrylic`）。在控件级批量差分中，非纯色后景统一采用固定、可复现的**合成底板**纹理验证半透明画刷叠色精度，不依赖实时桌面窗口捕获。
- **三类控件清单与先映射后迁移策略**：全量组件划分为「WinUI 3 基准对齐控件」「WinUI 3 缺失待补控件（含核心必补与 Community Toolkit 选补）」与「本框架自有独有控件」三类；先在清单与差分系统中统一以 WinUI 3 官方规范名为主键建立映射，待清单确认后再分批执行代码标识符重命名。

## 备选方案

- **所有控件拼成一张超大巨型图集**：一旦修改单个控件或新增状态，整张大图排版坐标漂移，导致其它未改动控件缓存连带失效；按「单控件 × 单主题 × 单后景」分片可将失效半径严格限制在单个控件内。
- **仅按 `controlBounds` 裁剪对比区**：实现最简单，但会切掉超出布局矩形的外投阴影（Elevation）与外扩焦点环（FocusVisual），导致阴影与焦点态漏检。
- **保留整画布统计但压低 $\Delta E$ 阈值**：不同控件占画布比例悬殊（如 `Slider` 与 `CheckBox`），固定阈值无法同时适配大小控件，只有裁剪到有效对比区才能消除画布尺寸耦合。
- **直接用真实桌面 DWM 截图跑全量控件 × 后景矩阵**：窗口焦点、桌面壁纸与多显示器缩放会导致数千张截图无法跨机复现，且采集速度极慢。

## 后果

- `report.json` 与单用例元数据的 schema 升级：新增 `backdrop`、`roi`、`overLimitRatio`、`intrinsicMatches`、`fingerprint` 与 `cacheHit` 字段；展厅内的 `Pixel parity` 报告页同步展示 ROI 指标与缓存命中情况。
- 历史全画布 $\Delta E$ 基线作废：切换为有效对比区四重门禁后，控件局部的真实色差与固有高度偏差不再被背景或外部矩形掩盖，从而真实驱动后续的一致性修复。
- 自有独有控件明确豁免一对一 WinUI 截图差分，改由 `.agents/skills/fluent-control-design` 技能（Token 映射、圆角/描边阶梯、状态透明度与弹簧参数约束）进行家族风格与行为合规性巡检。
