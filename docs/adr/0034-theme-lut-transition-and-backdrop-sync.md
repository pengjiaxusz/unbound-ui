# ADR 0034：基于 4 KiB LUT 逐帧插值的框架级主题过渡与后景协同契约

- 状态：已采纳
- 日期：2026-11-24
- 关联：延续 `unbound-theme` 零重排/零实例重传不变量；衔接 ADR 0014（窗口外观账本）、ADR 0023（多窗口共享设备）、ADR 0030（可见性驱动节流）与 ADR 0031（控件能力边界）

## 背景

当前框架在深浅色主题（`Light` / `Dark`）、产品预设（`ProductPreset`）或品牌强调色（`AccentBrand`）切换时，直接将目标调色板一次性写入 4 KiB 主题 LUT，界面在单帧内从纯黑跳变至纯白（或反之），暗光环境下对人眼造成明显闪屏刺激。

`unbound-ui` 的渲染管线在结构上已将图元实例与具体颜色解耦：所有图元只存 `u16` 语义令牌（`Token`），着色器每帧经由 `theme_lut_bda` 实时查表，硬件清屏色亦由 `Token::SURFACE` 同步派生。但将瞬切升级为平滑过渡仍面临四类跨模块边界约束：

1. **多帧在途数据竞争**：`Renderer::lut_buffer` 当前为单份 4 KiB 宿主可见缓冲；在 `frames_in_flight >= 2` 下连续逐帧写入会与 GPU 尚未退役的上一帧产生读写竞争。
2. **色彩感知与透明端点伪影**：在线性 RGB 空间做黑↔白插值会导致暗部陡跳、亮部发平；若某令牌在单侧主题为全透明（`alpha == 0`），直接插值 RGB 会引入暗边或灰边。
3. **双路径后景的异构行为**：原生路径通过 `WindowAppearance` 账本下发的 `DWMWA_USE_IMMERSIVE_DARK_MODE` 仅支持二值布尔，无法逐帧插值；自绘路径的壁纸空间纹理在后台线程按代次异步重建，到达时间可能滞后于前景过渡起点。
4. **无障碍、多窗口与差分测试门禁**：开启系统「减弱动画」的用户不应被迫观看过渡动画；不可见（`Suspended`）窗口不应被过渡强行唤醒；无头与拼版差分采集必须保持确定性瞬切，避免采到中间帧并污染用例指纹。

## 决策

- **过渡形态与默认曲线**：框架默认采用**基于 4 KiB LUT 的全量颜色渐变**，每帧在 CPU 插值 512 个令牌并写入当帧 LUT 槽位，**严格维持“切主题不触发布局重算、不重传图元实例、不新增离屏渲染 Pass”的不变量**。默认时长 **240ms**，采用 `CubicBezier` ease-out 曲线；提供应用级配置入口允许覆写时长（设为 `0` 即关闭过渡）。
- **GPU LUT 环形缓冲**：将 `Renderer::lut_buffer` 扩展为按 `frames_in_flight` 分槽的环形缓冲（每槽 4 KiB，总计 `frames_in_flight × 4 KiB`），每帧写入当前帧槽位并通过 push constant 的 `theme_lut_bda` 指向该槽位偏移，彻底消除连续逐帧更新的 CPU/GPU 数据竞争；过渡收敛后调度器照常回落至 0% 占用。
- **Oklab 感知插值与透明端点处理**：
  - RGB 分量采用 `unbound-math::Color::lerp_oklab` 做感知均匀插值，Alpha 分量保持线性插值；
  - `Token::NONE`（槽位 0）恒定保持全透明，不参与插值；
  - 当任一端点的 `alpha == 0` 时，插值期间沿用非透明端的 RGB 分量、仅插值 Alpha，消除黑边与灰边伪影。
- **中途重入与平滑折返**：过渡尚未结束时若再次触发主题、预设或强调色变更，将当前帧正在呈现的插值调色板冻结为新的起点 `from`，目标切换为新 `to`；若为反向折返（回到先前方向），按已走进度按比例缩短时长（`duration * progress`），避免顿挫与跳变。
- **双路径后景协同**：
  - **自绘路径**：前景立即启动 LUT 过渡而不阻塞等待后台线程；新代次壁纸空间纹理就绪后，保留上一代纹理并在底层以双图元透明度叠化淡入（取前景剩余过渡时长，保底不低于 `150ms`），叠化完成后释放旧纹理。
  - **原生路径**：不在过渡起点立即翻转系统二值标记，而是延迟至过渡中点（`t >= 0.5`）经由 `WindowAppearance` 账本一次性下发 `DWMWA_USE_IMMERSIVE_DARK_MODE`，减轻前景尚未变暗/变亮而背景先猛闪的割裂感。
- **多窗口与可见性节流协同**：多窗口应用发生全局主题切换时，所有可见窗口共享同一触发时间戳同步推进；遵循 ADR 0030，处于 `Suspended` 停绘态的窗口不因主题过渡被唤醒，待下次恢复可见时直接吸附至目标终态（`t = 1.0`）。
- **触发范围与强制瞬切逃生舱**：
  - **走过渡**：运行期深浅色切换、跟随系统 `ThemeChanged`、以及 `ProductPreset` / `AccentBrand` 切换。
  - **强制瞬切（`duration = 0`）**：窗口首帧初始化、操作系统开启「减弱动画」（在 `unbound-platform` 补齐 Win32 `SPI_GETCLIENTAREAANIMATION` 与 Linux 桌面偏好查询及默认开启兜底）、应用显式配置时长为 `0`、以及无头渲染与差分/拼版采集模式。

## 备选方案

- **离屏快照空间过渡（如点击点圆形扩散或全屏叠化）**：优点是黑↔白中段无低对比度灰态，且能一并遮罩绕过 LUT 的内容；但需在切换瞬间分配全屏瞬态离屏纹理并新增全屏合成 Pass，显著侵入 `unbound-gpu` 帧图并增加显存峰值。考虑到框架默认诉求是护眼、零侵入与极致轻量，否决将其作为默认实现（未来若作为可选高级视觉效果可另行评估）。
- **在线性 RGB 空间直接插值**：无需 Oklab 转换，但黑↔白过程人眼感知亮度明显前快后慢，暗部突兀跳亮，护眼效果弱于 Oklab。
- **延长默认时长至 500ms**：虽能拉长亮度变化时间，但在桌面高频切换场景体感偏拖沓，且会让文字与背景在中段灰区停留过久反而降低可读性。
- **后景一律瞬切**：实现更简单，但自绘云母在暗↔亮瞬间整块跳色会抵消前景渐变的护眼收益，故仍为自绘路径提供双纹理叠化并为原生路径选择中点翻转。

## 影响

- `unbound-theme` 需维护过渡状态机与起止调色板快照，按进度产出插值 `ThemeLut`，并暴露统一的时长/禁用配置；
- `unbound-gpu` 需将 `lut_buffer` 升级为按 `frames_in_flight` 分槽的环形缓冲，并验证多帧在途连续写入的安全性；
- `unbound-platform` 需新增跨平台系统「减弱动画」偏好查询接口，供主题过渡及后续框架级动效复用；
- `unbound-app` 需在单窗与多窗运行器中统一驱动过渡帧调度、同步自绘双纹理叠化与原生 DWM 中点翻转，并在首帧/无头/差分模式强制瞬切。
