# ADR 0004：捕获期间的光标形状继承被捕获控件

- 状态：已采纳
- 日期：2026-11-19
- 关联：issue #23

## 背景

光标栈把“指针捕获”放在最高优先级，并在捕获期间固定推送手型光标。这带来一个用户可见的错误：在文本输入框内按下左键但尚未拖动时，光标立即变成小手；按住拖动选择文本时又变成抓取手。用户期望的是“只要指针在输入框里，就一直是工字光标”。

原来的优先级表把“捕获”当成一个**独立的光标请求方**，但它其实不表达任何形状语义——捕获只说明事件归属，不说明该控件希望显示什么光标。

## 决策

- 捕获槽位不再硬编码手型，而是**继承被捕获命中区域声明的光标**：
  - 文本区域：按下、拖拽选字、松开全程保持工字；
  - 非文本捕获（滚动条、可平移画布等）：沿用其声明光标，进入拖拽后切换为抓取手。
- 被捕获区域未声明光标时，沿用原来的手型兜底，避免无光标声明的自定义拖拽表面退化。
- 捕获优先级本身不变：它仍高于浮层、缩放手柄、画布工具与文本，只是槽位里的形状来自目标区域。

## 备选方案

- **只在拖拽时推抓取手，未拖拽时回落到命中区域光标**：改动最小，但文本拖选仍显示抓取手，只修了半程。
- **删除捕获来源**：滚动条拖拽划过文本区域时会被文本的光标抢走，方向反了。

## 后果

- 命中区域必须声明自己的光标；未声明的拖拽表面继续按手型处理。
- 每帧重算光标时需要按捕获节点回查命中区域，代价是一次线性查找（与现有的区域遍历同阶）。
- 光标形状现在依赖两处事实：捕获归属（输入层）与区域声明的形状（控件层），二者必须在同一帧内一致。
