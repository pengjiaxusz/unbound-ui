# ADR 0009：差分必须区分「无效用例」与「通过」，参考采集带内容有效性契约

- 状态：已采纳
- 日期：2026-11-18

## 背景

对 238 个用例的参考采集与 ROI 差分做独立审计后，确认现有链路会把错误判成通过：

1. **空白对空白必然通过**：`content_bbox` 对纯色图返回哨兵 `[0,0,0,0]`，包围盒门禁按 `0 == 0` 判等；ROI 色差全为 0，四门禁全部满足。当前 12 个通过用例里有 8 个属于这种情况（`TreeView` 与 `AppBarSeparator` 的 normal/disabled × light/dark）。
2. **参考截图可能根本没拍到控件**：批量槽位固定 `260×96`，而 `TreeView` 高 140、`CalendarView` 260、`TitleBar` 宽 420；88/238 个用例的 `controlBounds` 超出裁切画布，25 张参考图整图纯色。
3. **等待时序不可靠**：`350ms` 计时在窗口 resize 之前启动，渲染帧门禁只等 3 个 `Rendering` tick；10 秒超时后直接截图而没有非背景像素校验，空白会被静默落盘。
4. **缓存感知不到宿主变化**：参考侧指纹只含 SDK/OS/缩放/用例/规格，未包含采集宿主源码或采集配方版本；实际参考图出自旧二进制，与当前 `Catalog.cs` 不一致。

## 决策

- **差分结果三态化**：`pass`、`fail`、`invalid`。任一侧内容包围盒为哨兵 `[0,0,0,0]`、内容像素占比低于阈值（默认 0.1%）、或参考 `controlBounds` 超出图像时，一律记为 `invalid`，不得计入 `pass`。
- **参考采集内容契约**：槽位尺寸取 `max(基础槽位, controlBounds 外扩出血)`，允许负向出血；窗口 resize 后重新等待布局与合成；截图后必须在 `controlBounds` 内检测到非背景像素，否则重试，重试仍失败则整例失败并记录原因，禁止落盘空白图。
- **指纹纳入宿主与配方**：参考侧指纹加入采集宿主源码哈希与采集配方版本；本框架侧指纹加入 `unbound-text` 栅格化/塑形/图集源码哈希。任一变化使缓存失效。
- **设计性空白显式声明**：`Image`、`ContentDialog`、`TeachingTip` 等允许内容为空的控件必须在清单中声明 `expected_empty`，只有声明过的空内容才允许参与比较；未声明的空白一律 `invalid`。
- **ROI 门禁只作用于有效对**：`intrinsic_matches` 仅在参考显式指定宽高时启用；通用演示内容不得冒充参考内容，配对键必须包含 `control/state/theme/backdrop` 四元组。

## 备选方案

- **把空白直接判 fail**：能阻止假阳性，但无法区分“采集失败”和“控件画错”，报告会误导后续校准。
- **继续逐个用例开窗采集**：时序最稳，但 238 个用例的窗口创建/销毁成本高，无法支撑后续四后景矩阵。
- **只修 `content_bbox` 哨兵判等**：能消掉 8 个假通过，但仍会放过“参考图只有背景、ours 也画了背景”的情况，且无法发现越界裁剪。

## 后果

- 现有 12 个通过用例中至少 8 个降级为 `invalid`，历史基线作废；必须在修复采集后重新采集并重跑，得到真实基线。
- `report.json` 增加 `status`、`invalidReason`、`contentCoverage`、`referenceSourceHash`、`captureRecipeVersion` 字段；展厅报告页按三态展示。
- 采集失败不再静默产出图片，CI/本地跑批会在首个无内容用例上明确失败，避免“绿着的空白”。
