# ADR 0014：窗口外观意图账本、闭环契约与非缺口裁决

- 状态：已采纳
- 日期：2026-11-19
- 关联：issue #55 (#56, #57, #58, #59), ADR 0001, ADR 0005

## 背景

在支持双路径后景材质体系后，宿主若想在 Windows 11 上开启原生云母（Mica）或亚克力（Acrylic）窗口，框架此前缺少开箱即用的声明式入口。宿主必须在平台事件回调（如 `on_hwnd`）中获取原生窗口句柄，并自行拼装整条调用链路：

1. 翻译材质种类到 Win32 DWM 属性或 Accent Policy 取值；
2. 显式将交换链合成方式调整为预乘 Alpha（`SurfaceAlpha::PreMultiplied`）；
3. 逐帧推导并下发清屏 Alpha 到运行时与渲染器；
4. 维护已下发状态以避免逐帧重复调用系统属性带来的系统开销与视觉闪烁；
5. 处理深色模式标记的持续同步，否则浅色模式下后景长期被错误渲染为深色；
6. 探测操作系统构建号与驱动预乘能力，处理能力不足时的安全降级回退。

一个真实宿主（演示应用）为此维护了约 400 行状态机胶水代码。不仅实现繁重，更关键的是框架把一条带有严格不变量与协同关系的闭环链路，拆成了四个可以被各自写错的旋钮：
- 清屏 Alpha 与是否存在原生材质无绑定：误写为 0 导致表面不透明时呈现黑板，误写为 1 导致材质永远透不出；
- 低版本 Windows（如 Windows 10）对 DWM 材质调用存在“假成功”现象：API 返回成功但无法提供材质，若盲目设为透明清屏就会变成透明空壳；
- 深色标记与主题切换脱节；
- DWM 材质与 Accent Policy 自定义色调属于互斥通道，切回 DWM 材质前若未清除 Accent Policy 会导致旧色调永久残留。

为避免日后再次基于过期假设施工，在接入改造前清查并核实了以下四项既有事实：
1. **合成方式枚举已存在**：`WindowConfig` 现有 11 个字段且已包含 `surface_alpha: SurfaceAlpha`，底层也已具备“驱动不支持预乘则回退不透明”的能力回退机制；
2. **清屏 Alpha 有读无写**：运行器与渲染器中虽有读取 `runtime.clear_alpha()` 并传给渲染器的链路，但在框架内部此前零写入，初值恒为 `1.0`；
3. **深色标记只覆盖广播分支**：`set_window_dark_mode` 仅在系统广播的 `ThemeChanged` 事件分支中调用，建窗首帧与宿主主动切换主题（`set_theme`）均未覆盖，导致浅色模式下后景始终呈现为深色；
4. **演示应用不走运行器**：`apps/showcase` 自己实现了 `PlatformApp`，拥有独立的呈现链与设备管理；此前唯一的材质翻译与下发实现躺在演示应用私有模块中，无法被其他宿主复用，且平台层材质写入函数在整个框架 crate 内部此前零调用。

## 决策

### 决策一：外观意图以「账本 + 已下发值去重」收进框架

- 在 `unbound-app` 引入 `WindowAppearance` 账本结构作为窗口外观状态的单一事实源。
- **纯值进、Diff 出**：账本接收意图（`AppearanceIntent`）、平台能力（`AppearanceCaps`，含 Windows 构建号、预乘合成支持、Accent 导出可用性）与当前主题（`ThemeKind`），比对内部记录的已下发状态，输出当前帧需要执行的增量写入 `AppearanceDiff`（通道变更、深色标记、失焦锁定、清屏 Alpha）。
- **策略与执行严格解耦**：账本本身不持有窗口句柄，不调用任何系统 API，不创建 GPU 资源。具体下发执行交给宿主或通用运行器（`WindowedRunner` 与 `Showcase` 统一消费账本输出的 Diff 执行下发）。
- **通道互斥与时序闭环**：在账本内部统一处理 DWM 系统材质通道与 Accent Policy 亚克力色调通道的互斥逻辑；从 Accent 切回 DWM 时强制生成清除 Accent 的语义，消除色调残留隐患。

### 决策二：意图关闭时行为与改造前逐字节一致

- 当宿主未显式开启后景材质（即配置为 `None` 或 `Some(WindowBackdropMaterial::None)`）时，账本不产生任何系统调用（通道为 `None`、深色标记为 `None`、失焦锁定为 `None`）。
- 清屏 Alpha 保持 `1.0`（或保留宿主显式指定的清屏值），表面合成方式保持默认的 `Opaque`。
- 拒绝“顺手统一”已有正常运行的不透明窗口路径，确保渐进迁移过程安全可控，不引入无意识的破坏性改动。

### 决策三：「算不算接进框架」的完成定义与闭环判据

明确操作系统能力接入框架的质量准绳：

**完成定义（Definition of Done）**：一项系统能力要被算作已真正接进框架，必须同时满足以下四项要求：
1. **声明式意图入口**：提供配置字段（如 `WindowConfig::backdrop`）或运行时方法（如 `AppRuntime::set_backdrop`），宿主表达意图时不要求持有原生窗口对象或句柄；
2. **框架内闭环执行**：框架内部全自动完成参数推导、已下发去重与平台能力回退，宿主不需要了解底层系统通道数量与互斥细节；
3. **至少一个非演示应用的消费者**：除演示应用（`apps/showcase`）外，至少包含一个真实消费者（如 `crates/unbound-app/examples/10_win11_native_desktop_shell.rs`），杜绝专供展示的私有特例；
4. **无窗口可断言的行为测试**：在无真实窗口、无 GPU 的 CI 环境下，提供覆盖核心状态矩阵与 Diff 输出的纯值断言测试。

**闭环判据（Loop Closure Criteria）**：决定一项系统能力是必须由框架闭环、还是允许作为平台命令式函数保留。满足以下任一条件即**必须**框架内闭环：
- **(a) 每帧参与渲染决策**：如清屏 Alpha 必须逐帧与呈现管线协同；
- **(b) 存在跨调用不变量**：如多路写入互斥（DWM 与 Accent 互斥）、时序依赖（切回 DWM 必须先清理 Accent）、状态联动（失焦锁定）；
- **(c) 需与运行时状态持续同步**：如随操作系统主题广播、窗口首帧、表面预乘能力或 DPI 缩放持续联动。

### 裁决清单：同型缺口收敛与非缺口裁决

依据上述三条闭环判据，对平台层 10 项“已实现未接线”的同型接口进行裁决与收敛：

1. **唯一真缺口（已彻底闭环）**：
   - **窗口后景材质与深色标记**：同时满足判据 (a)（清屏 Alpha 逐帧协同）、判据 (b)（DWM/Accent 双通道互斥与先清后写不变量）、判据 (c)（与系统主题广播、建窗首帧、预乘能力持续同步）。已由 Issue #56、#57、#58 彻底闭环接入外观账本。
2. **低优先能力裁决（非框架缺陷）**：
   - **任务栏进度（Taskbar Progress）**
   - **系统托盘图标（Tray Icon）**
   - **托盘气泡通知（Tray Balloon Notification）**
   - **裁决依据**：这三项能力均为命令式、一次性触发的系统调用。它们不参与每帧渲染决策（不符合 a），不存在复杂的跨调用互斥通道与先清后写不变量（不符合 b），亦不需要与交换链、主题等运行时状态持续同步（不符合 c）。宿主按需直接调用平台函数清晰且不易出错，强行封装为声明式配置或每帧比对的账本属于低价值过度抽象。因此判定它们**不是框架缺陷**，后续仅需补充文档与用例说明。
3. **研究项裁决：沉浸式后景取值探测（Immersive Backdrop）**：
   - `DwmMaterial::Immersive`（Windows 11 24H2 / Build 26100+ 出现的未公开后景）：属于实验性质。在微软官方文档正式收录前，框架不盲目在稳定路径猜解未验证数值，作为研究项保留在既有 Issue（#29 / #55），账本中安全回退为不透明。

### 配置字段与文档契约

`WindowConfig::backdrop` 作为建窗时的声明式后景入口，其文档与实现保证：
1. **自动选预乘**：开启后景时框架自动将表面合成方式选为预乘 Alpha（忽略显式设置的合成方式）；
2. **自动派生清屏 Alpha**：根据材质类型与平台能力自动计算并下发清屏 Alpha，使原生材质透出；
3. **能力不足退回不透明**：当操作系统版本低于 22621 或显卡驱动不支持预乘 Alpha 时，自动退回不透明窗口（不向系统请求材质，清屏 Alpha 钳回 1.0），杜绝黑屏与透明空壳。

## 备选方案

- **在平台层提供辅助函数，由宿主在每帧回调中自行组合**：把去重、互斥通道时序与清屏 Alpha 推导继续留给宿主。宿主依然容易漏掉关键状态，无法根除透明空壳与浅色模式发黑问题。
- **直接在 `WindowedRunner` 内部硬编码下发，不抽象独立账本**：`Showcase` 等独立实现 `PlatformApp` 的应用无法复用，迫使其维护私有翻译，导致规则分裂；且无法在无窗口环境下对增量 Diff 进行微秒级纯值单元测试。
- **将所有平台层能力（包括托盘、进度条）全量包装为声明式账本**：缺乏使用场景支撑，增加大量无不变量约束的无用状态字段，导致运行时复杂度膨胀。

## 后果

- **使用体验简化**：宿主开启原生云母/亚克力从 400 行胶水减少到配置 1 个字段，运行时可通过 `AppRuntime::set_backdrop` 即时切换。
- **单一事实源**：`WindowAppearance` 成为框架内唯一的外观意图账本，`WindowedRunner` 与 `Showcase` 共享同一份翻译与下发规则，彻底消除了私有映射与规则漂移。
- **可测试性保障**：增量 Diff 计算作为唯一纯值接缝，脱离窗口句柄与 GPU 即可在微秒级完成 10+1 项关键断言矩阵覆盖。
- **架构决策规范化**：建立「算不算接进框架」的完成定义与三项闭环判据，为后续平台特性的接入提供了清晰的准入与裁决标准。
