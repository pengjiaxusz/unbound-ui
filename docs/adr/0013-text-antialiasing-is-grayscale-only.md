# ADR 0013：文字主路径统一使用单通道灰度抗锯齿

- 状态：已采纳
- 日期：2026-11-19
- 关联：研究文档《ClearType 与亚像素抗锯齿调研》、ADR 0010（AA 边缘豁免）、矢量与文本架构文档

## 背景

讨论文字渲染开关时，ClearType 经常被当作"更高画质的一档"提出：既然 DirectWrite 支持，为什么不把它做成运行时选项？

调研后确认它不是一档画质，而是**三路覆盖率、逐通道混合、1:1 物理像素**三件事的绑定：

- DirectWrite 以 `CLEARTYPE_3x1` 输出每像素 3 字节的 R/G/B 子像素覆盖率，没有单一 alpha；
- 合成必须逐通道进行，常规 `SRC_ALPHA / ONE_MINUS_SRC_ALPHA` 表达不了；
- 只有目标不透明、纹理与物理子像素 1:1、图层无旋转缩放时，结果才成立。

本框架的文本会进入分层合成、半透明/云母材质、可缩放画布，三条前提任意一条都不满足。更关键的是透明中间层：一个像素只有一个 alpha，无法承载三个独立覆盖率；微软文档明确写明 ClearType "not suitable for rendering text onto a transparent intermediate bitmap"，而灰度"can be rendered onto a transparent bitmap"。这不是效果折扣，是表示能力的边界。

同时，之前观察到的锯齿已经定位为 DirectWrite 参数错误（只做水平抗锯齿、开启网格拟合、相位缓存键少一位），修正后灰度路径的中间灰占比为 22.9%，swash 为 25.2%，画质已持平。也就是说，缺的不是 ClearType。

## 决策

- **主路径只使用单通道灰度覆盖率**，由 DirectWrite（Windows）或 swash（其他平台/彩色字形/距离场）生成，统一进 R8 图集，以单一 alpha 合成。
- **不读取系统 ClearType 调校参数**（gamma、增强对比度、ClearType 强度）。字重由着色器内的极性相关曲线补偿，保证跨机器像素确定、截图基线稳定。
- **不把 ClearType 做成运行时开关**。它无法与普通图元合批，也不是一个 uniform 能表达的差异；做成开关会产生大量"看起来能选、实际失效"的组合。
- **ClearType 只允许作为展台的独立对照展示**：1:1 不透明卡片、轴对齐、静态、不进入通用图元批次，卡上必须标注四项前提。
- **与距离场互斥**：SDF/MSDF 输出标量覆盖率，无法承载三路子像素覆盖率。画布等可缩放场景走距离场，UI chrome 走灰度覆盖率，两者不叠加。
- **未来若确有必要接入**，必须作为独立合成路径立项，至少满足：请求 ClearType 3x1 纹理、读取混合参数、图集增加三路覆盖率语义、着色器逐通道输出、启用 dual-source blending 或专用离屏合成、定位锁死 1:1 不透明轴对齐。不得以"加一个 flag"的方式混入现有管线。

## 备选方案

- **全量接入 ClearType**：在不透明、1:1 的静态 UI 上确实更锐，但代价是分裂出第二条合成路径、失去跨机器确定性，并且在画布、Mica、动画、半透明窗口上全部失效。收益只覆盖很小一部分场景，维护成本却落到整条文字管线。
- **跟随系统 ClearType 设置做灰度调校**：读 `IDWriteRenderingParams` 的 gamma 与对比度，让灰度字重贴近用户偏好。可行，但会让同一版本的渲染结果随机器变化，ROI 门禁与截图基线需要按机器校准；当前阶段确定性更重要，暂不采用。
- **维持现状但不记录决策**：实现不变，但"为什么不支持 ClearType"会反复被提出，每次都要重新调研。本 ADR 的作用是终止重复讨论。

## 后果

- 低 PPI 屏幕上放弃最后一档水平锐度；补偿手段是高 PPI、亚像素定位、字重曲线与更合适的字体，而不是子像素抗锯齿。
- 不会出现彩边；截图、录屏、视频编码、缩放与旋转场景下的文字表现稳定。
- ROI 与截图基线不随用户 ClearType 调校漂移。
- 任何新增文字渲染路径都必须遵守"单通道覆盖率 + 单一 alpha"的契约；违反时应在评审阶段拒绝，而不是等到合成异常再排查。
- 若未来显示硬件与合成模型发生变化（例如统一的不透明直接呈现路径成为主流），可重新评估本决策；届时先更新研究文档，再改 ADR。
