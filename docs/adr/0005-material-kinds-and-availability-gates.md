# ADR 0005：材质种类清单与各档可用性门槛

- 状态：已采纳
- 日期：2026-11-18
- 相关需求：issue #29

## 背景

系统公开的后景材质只有固定的一组取值，另有若干只在较新系统版本上出现、公开文档未收录的取值。如果把“Windows 11 的所有效果”理解成不限范围，后景子系统会一路吞下窗口圆角、边框色、沉浸式深色、标题栏高度等**窗口外观**——那些不是背景材质，由别的子系统负责。

同时，不同材质对宿主的前提要求并不相同：多数材质要求系统版本足够新**且**图形表面支持预乘合成；而少数材质还额外要求一条未公开的通道可用。门槛必须逐档声明，不能只有一个笼统的“原生可用”。

## 决策

- 材质种类限定为六档：**无、跟随系统、标准云母、云母变体、亚克力、沉浸式后景**。窗口圆角、边框色、沉浸式深色、标题栏高度不纳入材质种类。
- 门槛分三档声明：
  - **无**：无门槛，任何环境都可用。
  - **跟随系统、标准云母、云母变体、亚克力**：要求系统构建号不低于 22621 **且**图形表面支持预乘合成。构建号未知（非系统环境或探测失败）视为不可用。
  - **沉浸式后景**：额外要求构建号不低于 26100。它是公开文档未收录的取值，只在较新版本上生效，可能随系统更新消失或改变外观，因此定位为**实验档**：可用则提供，不可用则按门槛原因禁用。
- **亚克力色调子档**：亚克力默认走系统材质通道（色调由系统决定）。额外提供一个“自定义色调”子档，走另一条通道实现，需要自行从系统动态库解析未公开导出，并**单独判定**其可用性，不与其它材质共用门槛。
- 材质种类与门槛必须成对出现：任何一个材质种类都必须能回答“当前机器能不能用”，且答案附带可展示的原因。

## 备选方案

- **只做公开的五档**：不碰未公开取值，最保守；但用户在较新系统上会少看到一种系统确实在用的效果，与“全部支持”的目标相悖。
- **把所有 Windows 11 观感都收进材质种类**：能一站式切换，但后景子系统会背上窗口装饰的职责，与窗口外观子系统职责重叠且难以界定边界。
- **只声明一个统一的“原生可用”门槛**：实现最省，但用户选到不满足前置条件的材质时只能看到“不可用”，得不到原因，也无法区分是版本不够还是表面合成不支持。

## 后果

- 材质种类清单是封闭集合：新增一档必须同时给出它的门槛、它的系统请求值，以及它在无该材质时的回退行为。
- 实验档必须被显式标注，使用者与维护者都要知道它承担被系统更新改变的风险。
- 亚克力的自定义色调子档是唯一走非标准通道的材质，它的存在意味着“材质种类 → 系统请求”不再是严格的一一映射，需要一张显式的映射表而不是简单转换函数。
- 可用性判定需要按材质种类逐档求值，后景计划必须能回答任意一档在当前机器上的可用性。
