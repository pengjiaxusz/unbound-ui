# ADR 0002：自绘后景按窗口屏幕矩形取样壁纸空间纹理

- 状态：已采纳
- 日期：2026-11-18
- 相关需求：issue #18

## 背景

早期自绘路径把“当前窗口视口”当成纹理空间：每次窗口变大、变小或移动，都按窗口尺寸重新生成一张磨砂纹理并整张拉伸铺满窗口。这样能及时反映尺寸变化，但带来三个问题：

- 窗口移动时纹理内容跟着窗口走，看起来像贴在窗口上的壁纸，而不是桌面背景；
- 窗口尺寸每变一次就可能触发一次壁纸解码与 CPU 模糊；
- 同一壁纸在不同窗口上生成多份近似纹理，纹理内容与主屏构图没有稳定对应关系。

## 决策

- 自绘纹理按**主屏壁纸空间**生成：覆盖整块主屏、按铺满比例裁切、降采样磨砂后按主题着色。
- 窗口只从这张纹理上取自己所占的归一化子矩形：用客户区屏幕物理矩形与主屏物理矩形求交、归一化并钳制到 `0..1`。
- 窗口位置或尺寸变化只更新取样区域，不重新生成纹理；场景在同一帧内按新取样区域重建。
- 只有主屏尺寸、DPI 缩放、主题明暗、纹理分辨率上限或壁纸源变化才使旧纹理失效。
- 窗口部分越界时按主屏边界钳制；完全无交集时退回整张纹理，保证采样区域始终有效。

## 备选方案

- **继续按窗口尺寸生成**：实现最简单，但无法做到“背景不随窗口移动”，且移动与缩放会反复触发解码与模糊。
- **由系统实时截取窗口背后的内容**：构图最准确，但需要屏幕捕获权限、额外 GPU 通路与隐私处理，远超当前后景子系统的职责。
- **按窗口在屏位置裁切后再生成**：移动仍需重新生成，且多窗口无法共享纹理，成本更高。

## 后果

- 自绘纹理是主屏背景的一份近似，无法反映窗口背后其他应用的内容；展示页必须明确说明这一点。
- 主屏之外的副屏窗口仍采样主屏纹理，与系统云母只跟随主屏的行为一致。
- 窗口移动或缩放只需更新一张叠加图元的取样区域，生成请求保持不变；纹理生成、代次淘汰与失败回退逻辑无需改动。
- 纹理失效条件必须可单测：窗口位置与尺寸不进入生成请求，主屏尺寸、DPI、主题、分辨率上限与壁纸源变化必须使请求不匹配。
- 取样区域必须由平台提供客户区屏幕物理矩形，布局视口不得混入屏幕坐标；两者混用会在高 DPI 或副屏环境下产生偏移。
