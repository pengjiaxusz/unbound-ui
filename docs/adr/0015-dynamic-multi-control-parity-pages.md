# ADR 0015：动态多控件拼版页、瞬态采集载体解耦与用例指纹增量过滤

- 状态：已采纳
- 日期：2026-11-19
- 关联：Issue #74 (#75, #76, #77), ADR 0008

## 背景

在 ADR 0008 中，为了解决早期全画布全尺寸像素差分的吞吐瓶颈与背景稀释问题，系统采纳了“单控件状态拼版图集并切出紧凑单图”的采集方案。然而，随着基准对齐控件总数扩展至 66 个（涉及 2 套主题与 132 个独立批次），参考宿主（`tools/winui-reference`）的采集流程暴露了新的性能瓶颈：

1. **动效收敛等待次数过高**：每个控件独立成批，每次均需创建或重置窗口、执行可视树布局计算，并等待至少 350ms 的 VisualState 动画与合成动效收敛。全量 66 个控件在单主题下即需等待 66 次 350ms（超过 23 秒净等待），双主题全量采集需近一分钟，导致本地调试与 CI 反馈回路冗长。
2. **缺乏多控件联合采集能力**：开发者在调试相关联的一组控件时，无法将多个控件合并至同屏一次性核验视觉质感与排版协调性。
3. **旧备选方案的历史技术债务**：在 ADR 0008 的备选方案中，曾讨论并拒绝了“所有控件拼成一张超大巨型图集”，理由是：“一旦修改单个控件或新增状态，整张大图排版坐标漂移，导致其它未改动控件缓存连带失效；按「单控件 × 单主题 × 单后景」分片可将失效半径严格限制在单个控件内。”但这一假设将“采集载体”与“产物单图”强行绑定，限制了多控件合并采集的可能性。

## 决策

### 决策一：瞬态采集载体与切片独立产物彻底解耦

- **瞬态采集载体（Transient Capture Container）**：
  将多控件动态拼版页（Dynamic Parity Page）严格界定为运行时的瞬态采集载体。其生命周期仅存在于“可视树测量 → 共享单次 3 帧渲染与 350ms 动效等待 → 单次 `RenderTargetBitmap` 导出整页像素缓冲 → 槽位包围盒内存切片”这一闭环过程。
- **切片独立产物（Independent Output Slices）**：
  持久化落盘产物依然是严格解耦、颗粒度精确到单个状态的紧凑单图 `<Control>_<state>_<theme>[_<backdrop>].png` 及同名 JSON（记录独立的 fingerprint、relative controlBounds、DPI 缩放等）。
- **坐标漂移与指纹缓存解耦**：
  无论控件被排在瞬态拼版页的哪个物理坐标，裁剪时均通过 `control.TransformToVisual(Host)` 获取其相对视觉几何，并外扩 16 DIP 出血保护。产物单图仅反映控件局部内容与出血边缘，整页排版坐标的平移或重排**完全不改变切片单图像素与单用例指纹**。
- **正式取代 ADR 0008 历史顾虑**：
  本决策彻底消除了 ADR 0008 备选方案关于“排版坐标漂移导致其它控件缓存连带失效”的顾虑，正式取代该历史假设。下游 Rust 离屏差分器（`showcase --parity-run`）与 CIEDE2000 四重门禁零改动 100% 向后兼容。

### 决策二：多控件 2D 流式装箱（FFDH）与视口溢出安全分页

- **确定性标准视口**：
  统一采用固定 `1920×1080 DIP` 的画布尺寸作为动态拼版页的标准承载视口，在不同开发机与无显示器 CI 环境下均具备确定性，杜绝因窗口尺寸不确定造成的溢出裁剪。
- **高度降序装箱（FFDH：First-Fit Decreasing Height）**：
  在装箱规划器（`PlanPages`）中，按槽位期望高度降序排列各用例，消除高矮混排造成的纵向空隙。行内按 X 轴累加宽度，超宽自动换行，使全量 66 个基准控件单主题稳定收敛在 2~3 页内（动效收敛等待次数从 66 次骤降至 2~3 次，吞吐量提升 30 倍）。
- **视口溢出安全分页状态机**：
  当新行高度累加超过 1080 DIP 安全视口上限时，装箱规划器自动截断当前页并顺延开启下一页（`pageIndex++`）。
- **单窗口就地清空与生命周期复用**：
  翻页时保持单个 `Window` 实例，在就地完成 `Host.Children.Clear()` 后挂载下一页控件槽位，彻底消除重复创建/销毁 HWND 带来的窗口闪烁与 DWM 重建延迟。

### 决策三：用例指纹增量前置过滤（Pre-Filtering）

- **前置过滤闭环**：
  在候选批次送入 `PlanPages` 装箱之前，基于用例指纹（SDK 版本、OS 构建号、规格描述、光栅化缩放、采集宿主源码哈希等）比对磁盘已有的切片产物。
- **过滤准则**：
  - 只有当控件内存在至少一个未命中状态或该控件被显式指定（或指定了 `--no-cache`）时，才将其送入装箱规划器；
  - 已全部命中缓存的控件**完全不进入装箱规划器，不分配版面槽位，不参与可视树测量（`MeasureSlotSize`）**；
  - 修改或缺失单个控件时，仅装箱并渲染该控件所在的 1 页，实现零冗余增量闭环。
- **毫秒级退出保障**：
  若某主题下的所有控件均已命中缓存，系统直接打印 `[cache-hit]` 并完全跳过当前主题所有拼版页的装载、渲染与等待，达到毫秒级退出。

### 决策四：总览存档契约演进（`--save-sheet`）

- 当开发者或自动化调试流程指定 `--save-sheet` 时，系统在输出独立单图切片的同时，额外输出按页码归档的总览图：`page_{pageIndex:D2}_{theme}_{backdrop}_sheet.png`；
- 配套写入包含当前页所有槽位相对整页裁剪框（`cropBounds`）与控件局部相对边界（`controlBounds`）的 `page_{pageIndex:D2}_{theme}_{backdrop}_sheet.json`，供人工速览与整页视觉核对。

## 备选方案

- **维持 ADR 0008 单控件独立拼版**：
  每个控件占用一个独立批次并等待 350ms，全量 66 控件双主题耗时近一分钟，日常多控件迭代体验差。
- **静态固定行列网格排版**：
  由于控件尺寸悬殊（如 `Button` 120×32 DIP vs `CalendarView` 300×320 DIP），固定网格会造成巨大空间浪费，导致分页数剧增，无法收敛至 2~3 页。
- **产物直接输出整页大图并由 Rust 端进行大图差分**：
  破坏了单用例缓存隔离性，一旦某一个控件变更，整页所有控件的参考基准被迫重跑，背离了细粒度精准回归原则。

## 后果

- **采集吞吐量大幅跃升**：全量 66 个基准控件单主题动效等待从 66 次降至 2~3 次，采集时间从近一分钟压缩至数秒以内。
- **二次运行零等待**：在未修改控件规格时，增量指纹前置过滤实现毫秒级跳过（无任何可视树加载与测量）。
- **零破坏性向后兼容**：切片产物格式、命名与 JSON 元数据与旧版保持 100% 一致，Rust 侧离屏差分器与既有 CIEDE2000 四重门禁完全无感知消费。
- **多控件即时调试就绪**：支持 `--control Button,CheckBox,...` 将任意选定控件组合在同屏渲染，加速局部控件联调。
