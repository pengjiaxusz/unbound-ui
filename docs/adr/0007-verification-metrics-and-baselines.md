# ADR 0007：验收指标落地方式

- 状态：已采纳
- 日期：2026-11-18
- 相关需求：issue #29

## 背景

本次改造的目标之一是让自绘路径与原生路径观感接近，但“接近”如果不落成可复现的检查，下一次改动就会把它悄悄改回去。

更棘手的是：现有的截图通道写的是**渲染器回读像素**，即应用自己的绘制结果。系统材质是由桌面合成器在窗口**背后**合成的，根本不在这块像素里。因此“原生截图 vs 自绘截图”的像素差分，用现有通道根本做不出来——它只能拍到自绘，拍不到原生。

## 决策

- 验收分两套，互不替代：
  1. **无头数值断言（进 CI）**：对自绘纹理的输出做统计断言——空间梯度能量（结构是否被抹掉）、明度带宽、色相保真度。它锁定的是**自绘自身的不变量**（例如换壁纸不改变磨砂强度），不追求与原生逐像素相等。
  2. **屏幕捕获对照（人工验收基线）**：新增一条从屏幕设备上下文取样的捕获通道，在同一壁纸、同一窗口位置下分别切到原生与自绘，产出并排截图与差分热力图，供人工判断“观感难分辨”是否达成。
- 磨砂锚点的数值按两步标定：先用人工目测确定基准值，再用无头数值断言把它固化成不变量。
- 纹理分辨率上限先保持不变，由无头断言观察梯度量化后的台阶严重度再决定是否提高——分辨率上限是**测量结论**，不是拍板参数。

## 备选方案

- **只做人工 A/B 判断**：成本最低，但没有回归防线，观感一旦漂移无人察觉。
- **只做无头断言**：能锁住不变量，但回答不了“与原生到底差多少”，而这正是本次问题的核心疑问。
- **复用渲染器回读做原生/自绘差分**：这条路根本不通——回读只包含应用自己的绘制结果，系统材质不在其中。必须新开屏幕捕获通道。
- **把屏幕捕获做成 CI 门禁**：捕获结果依赖桌面环境、壁纸、窗口位置与当前运行的系统版本，不具备可复现性，不适合作为门禁。

## 后果

- 出现两条独立的捕获路径：渲染器回读（只含应用绘制结果）与屏幕捕获（含系统合成结果）。两者的像素格式与坐标系必须显式对齐，差分才有意义。
- CI 门禁守不变量，人工验收守观感；两者不可互相替代。
- 磨砂锚点数值的标定是两步流程：目测给初值，断言把它钉死。
- 无头断言只针对自绘管线，不依赖系统版本，因此可以在任意环境稳定运行。
