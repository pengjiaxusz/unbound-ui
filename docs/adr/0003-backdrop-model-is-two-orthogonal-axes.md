# ADR 0003：后景模型正交为「材质种类 × 来源」两轴

- 状态：已采纳
- 日期：2026-11-18
- 相关需求：issue #29

## 背景

现状是两个各管各的枚举：一条“路径”枚举决定走原生还是自绘，另一条“材质”枚举决定向系统请求哪种材质，两者互不知情。材质枚举里只有一种材质被真正下发，平台层其实已经备好了五档系统材质，其中三档是死代码。

要接入 Windows 11 的整套系统材质，若继续在两个枚举上打补丁，会出现三个问题：

- “这一格组合选不了”这种判断无处安放，只能散落到各个调用点；
- 每加一种材质，路径与材质的笛卡尔积都要人工枚举一遍；
- 用户在界面上看不出自己选的是“哪种材质”与“走哪条路”，回退时也无从解释。

## 决策

- 引入**材质种类**轴：无、跟随系统、标准云母、云母变体、亚克力，以及仅在较新系统版本上可用的沉浸式后景实验档。
- 引入**来源**轴：自动选择、系统原生、引擎自绘。
- 后景计划一次性算清（材质种类，来源）组合的全部结论：实际生效组合、清屏透明度、根背景透明性、系统材质请求、纹理规格与取样区域。
- 材质种类为“无”时，来源轴折叠：不请求任何系统材质，也不生成任何纹理。
- 组合是否可用由后景计划判定，并给出**不可用原因**；界面层只负责呈现，不得自行推导可用性。

## 备选方案

- **拍平成一维枚举**：把“材质 × 来源”展开成 `云母(原生)`、`云母(自绘)` 这样的变体。变体数量随材质数翻倍，回退规则无处安放，每加一种材质就要重写一遍匹配逻辑。
- **只补齐材质枚举、路径选择逻辑不动**：改动最小，但“系统不支持该材质”与“该材质没有自绘变体”两类不可用原因无法区分，回退路径也无法穷举测试。
- **让界面层直接决定可用性**：界面知道当前构建号与材质列表，可用性判断最直观，但同一套规则会在展台、宿主与未来其它宿主之间复制三份。

## 后果

- 后景公共接口发生破坏性变更：路径枚举与材质枚举的语义与命名都会改变，所有调用方必须同步迁移。
- 后景计划必须穷举「材质种类 × 来源 × 平台能力」的组合，并断言每种组合的生效结果与回退原因。
- 材质种类与来源在文档与界面上必须同时可见，避免“选了云母变体却落在自绘路径上”这类误解。
- 自绘路径的覆盖边界成为独立决策：并非每种材质都需要自绘变体，缺少变体的材质与来源的组合按“组合非法”处理。
