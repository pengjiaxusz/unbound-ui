# ADR 0001：后景合成方式在窗口生命周期内固定

- 状态：已采纳
- 日期：2026-11-18
- 相关需求：issue #17

## 背景

双路径后景允许用户在原生云母、自绘壁纸与关闭之间切换。早期实现按“当前实际生效路径”选择表面合成方式：原生路径用预乘 alpha，其余路径用不透明。于是从关闭或自绘切到原生时，必须重建交换链并重设合成方式，过程中会出现一帧黑屏或透明闪底；反向切换同样要重配呈现链。

问题不在重建本身，而在于把**用户选择**误当成了**平台能力**：一台机器是否支持预乘合成，在整个窗口生命周期内不会变化。

## 决策

- 启动时只探测一次原生能力，并据此固定表面合成方式：能力可用即预乘，否则不透明。
- 用户的模式选择只决定清屏 alpha、DWM 材质请求与根背景透明性，不再参与合成方式推导。
- 能力可用的机器即使当前选择关闭或自绘，也保持预乘合成；非原生路径用不透明清屏维持视觉不透明。
- 交换链重建只允许由驱动过期、表面尺寸变化或设备丢失触发，模式切换绝不触发重建。

## 备选方案

- **每次模式切换都重建交换链**：实现简单，但往返切换必然闪黑，且重建期间窗口内容不可控。
- **只在透明性翻转时重建**：比每次都重建少一半重建次数，但仍无法消除最关键的“切到原生”闪黑。
- **为每条路径各建一条交换链**：内存与同步成本更高，切换时仍需处理两条链的呈现衔接，收益不抵复杂度。

## 后果

- 能力可用的机器会放弃呈现缩放（预乘合成不支持该标志），这是保证切换无黑屏的代价；需要缩放时由渲染端自行适配。
- 非原生路径必须把清屏 alpha 固定为 1 并绘制不透明内容，否则会看到桌面穿透；该约束由后景计划统一输出，宿主不再自行判断。
- 透明度变化必须可单测：计划层穷举四种模式与两种能力组合，断言合成方式恒定；宿主层不再出现“按生效路径选合成方式”的分支。
- 新增后景模式时，只能扩展清屏与材质请求，不得引入新的合成方式分支。
