# ADR 0001：输入法组合文本是真实缓冲区内容

- 状态：已采纳
- 日期：2026-11-18
- 关联：issue #6「统一 IME 组合输入与文本编辑」

## 背景

早期实现把输入法组合串与应用文本分成两套镜像：平台层维护一份待提交缓冲，应用层再维护一份“预编辑文本”，绘制时把两者拼起来显示。这带来一连串问题：

- 提交时容易把同一段文本插入两次，或者组合串在切换焦点后凭空消失。
- 插入符、选区、剪贴板与可见文本不一致，组合期间无法正常使用方向键与删除。
- 宿主轮询待提交缓冲，导致“平台上报一次、宿主再插入一次”的重复路径。
- 每个自绘输入框都要自己处理组合串，行为无法统一。

## 决策

组合文本一律写入**真实的编辑缓冲区**，并记录它占据的字节区间（组合区间）。输入法事件只表达三件事：

1. **预编辑**：用新的组合串整体替换旧组合区间；
2. **提交**：用提交串整体替换当前组合区间，没有组合区间时按普通插入；
3. **取消**：恢复组合开始前的文本与插入符快照。

平台层只上报系统输入法的状态（组合串、是否启用、是否取消），不再缓存“待提交文本”，也不再提供取出待提交内容的接口。运行时分发输入法事件时，优先交付给当前聚焦的文本控件；控件消费后，应用层不再收到同一事件。

## 影响

- 光标、选区、水平滚动、撤销、剪贴板全部按普通文本工作，无需为组合态写特例。
- 提交天然是“替换区间”，结构上排除了重复插入。
- 失去焦点、按 `Esc`、收到任何非输入法编辑事件时统一取消组合，半成品不会残留。
- 自绘输入框只需要共享同一份编辑核心与一组输入法事件，不再各自拼装显示文本。

## 备选方案

- **保留双镜像并加强同步**：需要在每个输入框、每次提交与每次焦点切换时手工对齐两份文本，正是历史 bug 的来源，放弃。
- **组合串只存在于平台层，提交时一次性插入**：组合期间无法显示光标、选区与内联下划线，也无法正确处理“组合中删除/移动”，放弃。

## 后续约束

- 任何新增的自绘文本输入都必须使用共享编辑核心，禁止再引入“预编辑文本”字段。
- 平台层若新增输入法能力，只能扩展事件语义，不得恢复待提交文本缓冲。
